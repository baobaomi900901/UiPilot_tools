# OCR Panel 与双入口交互设计

状态：用户已确认（2026-11-06）。本文替代上一版 OCR 插件的主列表结果交互；已有 mainResult 图片插件仍保持兼容。

## 目标与命名

- 插件显示名称与默认命令均为 `ocr`，命令入口 `/ocr`。
- 插件 ID、源码目录改为 `com.uipilot.ocr`；新身份首版为 `1.0.0`，交付包为 `com.uipilot.ocr-1.0.0.uipilot-plugin`。旧交付包不覆盖。
- 参考 `com.uipilot.translate` 的标准 Panel、左右内容布局、源选择、宿主状态栏、复制及键盘焦点规则。
- 首期服务源只有“百度 OCR”，继续使用主程序中已配置的百度凭据。
- 本任务同时包含宿主图片 Panel 能力与插件实现；插件界面和业务编排仍保留在插件包中。

## 方案选择

采用“通用图片输入能力 + 标准 Panel 插件”。宿主提供图片接收、会话归属和服务授权；插件实现预览、识别文本、源选择和复制。

宿主内置专用 OCR 页面会把插件业务放进主程序，后续多插件扩展不自然；独立窗口不能满足留在主窗口中操作的要求，因此不采用。

## 两种入口

### 先粘贴图片

1. 普通主输入框接收图片，显示临时缩略图并列出已安装、启用、兼容且声明 `image.ocr` 的命令。
2. 按能力匹配，不检查特定插件 ID；取消现有针对百度插件 ID 的优先排序。结果使用现有统一命令排序，允许方向键选择多个 OCR 插件。
3. 选择 Panel OCR 命令后回车，进入该插件并把同一图片快照交给它。顶部切换为所选命令 tag，本插件为 `ocr`；图片在内容区左侧显示，不继续占据主输入框。
4. 焦点保留在 tag 后的主输入框；Panel 就绪后自动识别一次。选中列表项本身不识别。

### 先进入 `/ocr`

1. 输入 `/ocr`，选择匹配项并回车，直接打开空 Panel，不要求图片或文字参数。
2. 顶部显示 `ocr` tag，焦点在主输入框；左侧显示图片空状态，右侧为空，复制不可用。
3. 在主输入框粘贴图片后，图片进入左侧预览并自动识别；之后每次有效换图都自动识别最新图片。
4. 两个入口进入后使用完全相同的 Panel 状态与换图逻辑。

## 面板与键盘

- 内容区保持左右两栏：左侧图片预览，右侧识别文本域。沿用翻译插件的间距、字体、主题变量与工具按钮，不增加第二个主搜索栏。
- 图片等比例完整显示。右侧保留换行并可滚动；下方有复制按钮和 OCR 源选择按钮。源选择菜单目前只列“百度 OCR”，切换到同一源不重复请求。
- 文本域按可编辑设计：复制当前文本域完整内容，修改文本不触发 OCR；有效换图时清空旧文本并等待新结果。
- 无图、识别中、无文字、失败时复制禁用；空状态、加载和错误不改变两栏几何。失败提供显式重试，不自动循环重试。
- 左侧提供清除图片入口；清除后左右恢复空态、旧识别失效，仍留在 `ocr` Panel。
- 主输入为空时显示“粘贴图片”。普通文字输入与 IME 保持正常编辑，不将文字输入当成 OCR 请求。
- 主输入框光标位于起点且无选区时，Backspace 沿用现有 Panel 规则移除 tag、退出 Panel并释放本次图片；输入法组词期间不触发退出。
- 普通启动器中已有临时图片且输入为空时，Backspace 可移除图片。
- Esc 优先关闭菜单，再按现有 Panel 返回规则退出；退出或隐藏后重新进入为空，不恢复图片或正文。
- 主输入框为空且已有结果时，Enter 可复制当前文本；文本域内 Enter 正常换行，按钮上的 Enter 执行按钮动作，长按不重复执行。Tab/Shift+Tab 覆盖文本域及工具按钮。
- 复制成功通过宿主状态栏显示“已复制”，保留 Panel 和焦点；复制失败保留文本以便重试。

## 宿主能力与插件边界

- 以 Host `0.21.0` 为新能力门槛，API/schema 仍为 v1。同步 Manifest、Rust/CLI 校验、SDK 与开发文档。
- 保留 Host 0.20.0 的 `submit + mainResult + image.ocr`，新增 Windows 单命令 `submit + panel + panel.runtimeActions + ui.panel + image.ocr`。不顺带开放 Window 或多命令 Panel。
- 主程序继续只在明确的输入框粘贴动作中读取图片，不开放任意剪贴板读取；保持已实现的图片格式、大小与内存边界。
- 图片从启动器交接给所选 Panel 后归属于该 Panel 会话；外部启动器图片状态清除时不得误清理已经交接的图片。
- Panel 获得宿主生成的只读图片描述符、不透明引用、图片修订号与有界预览。预览只用于显示，百度仍使用原标准化快照；不把原图 Base64 塞入通用 Panel 请求或存储。
- 初始图片和后续变化统一由宿主发送会话绑定的图片变更通知。更新预览不等待 OCR 完成，也不抢走主输入焦点。通知在 Panel Ready 后投递，未就绪时仅保留最新修订。
- Panel 的图片识别请求显式携带图片引用；宿主验证当前 Panel 身份、会话和最新图片，再将同一快照绑定到该次 `onPanelAction` 的只读 `invocation.image`。业务 `payload` 只携带源选择，不用插件自定义 payload 建立权限。
- 百度服务扩展到上述当前图片 Panel action，仍调用 `api.services.baidu.ocr({imageId: invocation.image.id})`。保留原 mainResult 服务合同，不以发布保护标记判断插件协议。
- `onCommand` 只初始化 Panel，不调用 OCR；插件在 Ready 后或有效图片变更后，通过 `panel.request` 发起识别。复制复用现有 `panel.clipboard.writeText`。
- 预览与新增桥字段使用下述独立上限，不提高所有插件的通用 JSON/网络上限。

### 新增公开桥合同

- 对符合上述新 Panel 形态的内容页提供可选 `panel.onImageChanged(handler)`，返回取消订阅函数。接收器在首次 `onUpdate` 注册前安装；每个当前会话在 Ready 后投递一次最新快照，此后仅在图片修订变化时投递。退出后旧接收器和排队事件失效。
- 同一能力提供会话绑定的 `panel.clearImage(): Promise<void>`，仅清除当前 Panel 图片并发布新的空图片修订；不清除其他会话的图片，不调用 OCR，旧会话调用返回 `ExpiredPanelSession`。用于左侧清除按钮。
- 事件为深只读 `{ sessionEpoch: U64Decimal, revision: U64Decimal, image: PanelImageSnapshot | null }`；清除也递增修订号。`PanelImageSnapshot` 是现有图片描述符字段加 `previewDataUrl`。其 `id` 仅属于当前 Panel 会话和图片修订，不等同于 Runtime 请求图片 ID。
- Panel 预览为最长边不超过 512px 的 PNG，编码上限 40 KiB；必要时逐步缩小派生预览以满足预算，整个图片事件上限 64 KiB。预览等比例居中显示，不超出实际像素尺寸放大。原图限制不变，识别不使用预览。
- `PluginPanelRequest` 新增可选 `imageId: string`，长度最多 512；省略时保留旧请求行为。该字段只允许具备图片能力的当前 Panel 使用；错误字段或类型返回 `InvalidPanelRequestError`，会话过期返回 `ExpiredPanelSession`，非当前图片引用返回 `PanelRequestCancelledError`。用户业务 `payload` 不参与宿主图片权限判定。
- 成功接纳图片请求后，`PluginPanelActionInvocation` 增加可选只读 `image: PluginImageDescriptor`，其中 `id` 为本次请求专用引用。未携带图片请求的旧 action 不获得该字段。调用百度服务时必须使用此引用，而不是事件里的 Panel 图片 ID。
- 本插件请求为 `panel.request({ action: 'recognize', imageId: snapshot.id, payload: { providerId: 'baidu' } })`；Runtime 返回现有 `{requestId, data}`，成功 data 为 `{ok:true, text, lines}`，失败为有界固定 `{ok:false, code, message}`。文本使用现有 16 KiB 上限，回复仍受既有 64 KiB 合同约束。
- 主窗口进入 Panel 的内部命令新增可选图片引用，主输入框后续粘贴复用宿主导入入口并显式指定当前 Panel 归属。宿主核验调用窗口与 Panel 身份，拒绝用主窗口或其他插件的旧引用替换新会话图片。

## 异步与失败行为

- 插件最多保留一个在途识别与一个最新待处理图片。连续换图 A→B→C 时，仅 C 有权更新右侧；不排队识别所有中间图片。
- 换图立即清除旧文本并撤销旧图片请求的结果权限；已发出的远端请求不能保证撤销，但迟到结果不能显示或重新打开窗口。
- 重复就绪通知、主题更新、布局调整不触发重复识别。切换实际不同的有效源或点击重试才对当前图片重新识别。
- 损坏或超限图片不替换原有效图片和文本，显示明确导入错误。清除图片不发送 OCR 请求。
- 隐藏、退出、禁用、卸载、更新、撤权和凭据变化使旧会话/请求失效。重新授权不能复活旧响应。
- 网络、权限、配置、认证、额度、空文字与超长结果分别反馈；不截断后冒充完整复制。文本及图片不新增持久化历史，凭据仍仅由宿主持有。

## 身份变更与交付

- `com.uipilot.ocr` 是新插件身份，安装时按正常流程确认 `ui.panel`、`clipboard.write`、`network.https`、`credentials.baiduOcr` 和百度主机授权。
- 不自动继承旧插件授权、收藏或快捷键，也不自动卸载用户已经安装的 `com.uipilot.baidu-ocr`；提供手动停用旧版的升级说明，避免重复列表项。
- 仓库业务源码与当前文档切换到新名称，历史设计与旧包作为历史记录保留。主程序中的百度服务名称继续表示供应商。

## 验收

1. 两条入口均进入相同 OCR Panel；有图自动识别，无图空态且主输入保持焦点。
2. 至少两个不同 ID 的 OCR 插件夹具共同出现在图片列表，选择后各自正确交接；旧 mainResult OCR 仍可执行。
3. 顶部为可退出的命令 tag，图片位于左侧；退格、Esc、Tab、IME、主输入 Enter 和文本域 Enter 符合上述规则。
4. 换图、清除、快速连续粘贴、隐藏、撤权和迟到回复不能显示或复制旧结果。
5. 使用实际 Host 调度顺序覆盖进入、图片绑定、Panel Ready、action 派发、服务响应和复制，避免只测试 manager 方法或孤立假端口。
6. 插件 Runtime、Panel 模型/DOM、SDK、Manifest/CLI、宿主桥及相关回归通过；同时检查包目录和归档。
7. Light/Dark、真实粘贴、百度请求和系统复制由用户手动验收；不使用 Computer Use，也不把离线测试当作原生验收。

## 自检

两种入口共享同一状态机；OCR 插件与 OCR 服务源分别管理；空入口不请求、换图才请求；旧结果按图片修订失效；插件身份变化不静默迁移授权。本设计尚未表示功能已经实现。
