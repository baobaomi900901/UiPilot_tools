# User-selected text file import design

Date: 2026-10-26. Host0.13.0, JSON workbench1.1.0. This is authorized host-program development within the local-plugin foundation; no online install/publishing. Standing user authorization covers autonomous design, implementation and review; native acceptance remains user-operated.

## Goal and scope

A window plugin can explicitly let its user choose one local UTF-8 text file and receive its bounded contents. The existing JSON workbench imports it as an unsaved draft, then reuses Runtime format/save/load. This closes one M5 file workflow without introducing arbitrary filesystem access.

Considered: (1) direct window capability (chosen): native dialog doesn't occupy a Runtime slot; integrates naturally with existing workbench; (2) Runtime picker API: a human dialog can exceed Runtime watchdog and unnecessarily hold scheduling; (3) persistent file handles/read/write API: substantially broader lifecycle and authorization contract. Panel/mainResult integration, saving files, directory enumeration, multi-select, binary content, persistent handles and file watching are deferred.

## Public contract and versions

New permission `files.openText`, Windows-only, minimumHostVersion >=0.13.0, legacy submit/window output with ui.window declared. It does not require window.runtimeActions by itself. No other output modes may declare it. Existing permission update consent applies; denial preserves prior install/config/data/bindings. Manifest/API/state schemas stay unchanged. Update actual PublicPluginHost::current and all release/CLI targets to0.13.0; keep old package minimums unchanged.

Only opted-in Window content exposes optional readonly `files` facade on window.uipilotPluginWindow. Exact public call `files.openText(): Promise<Readonly<{name:string,text:string,byteLength:number}> | null>` takes no arguments. null means user cancelled. name is basename only, never a path; byteLength is original file byte count, including optional BOM. The result/facade is frozen. Empty text is valid. Maximum original size8192 bytes; UTF-8 BOM may be removed once before decoding, other whitespace/newlines remain exact. Invalid UTF-8 or NUL fails; UTF-16 is not converted. No JSON parsing in Host.

Fixed errors with sanitized names: FileOpenBusyError, ExpiredWindowSessionError, FileOpenPermissionError, FileOpenUnsupportedError, FileOpenTooLargeError, FileOpenEncodingError, FileOpenFailedError. Invalid no-argument call rejects TypeError in JS before invoking. Unsupported includes nonlocal/nonregular/device/reparse targets. Other platform fails closed. Do not log path, basename, text or native error bodies.

Bootstrap captures session and document generation in each files facade, validates current active/not-updating session, keeps one pending call and rejects stale completion, exposing a new facade on a new session. Old captured functions cannot borrow new identity. Validate exact reply shape/types, byte bounds/text consistency under BOM allowance and no NUL; don't reuse generic bounded JSON rules that reject legitimate content strings. Callable only after update/ACK just like window request. No direct Runtime API; no broad Tauri dialog/filesystem exposure. The plugin example invokes only from its user button; the Host does not claim to prove JavaScript click provenance. The native chooser is the user authorization for each selected file.

## Authority and native lifetime

Add one private IPC `plugin_window_open_text` allowed only to plugin-window-content (AppManifest, command registration, generated permission and capability in same change). The real WebView label determines caller; no public path or pluginId argument. Internal session/document strings must be canonical nonzero u64. Reuse full WindowActionIdentity: exact owner plus content label, session and document generation.

Controller admission checks current visible, active, nonrevoked document/session. Manager checks confirmed installed/enabled/nonfault/no recovery, matching config/runtime generation, activation/admission, legacy submit/window and both ui.window/files.openText declarations and grants. Use a narrow manager authorization operation modeled on existing window action checks, without Runtime scheduler reservation. Controller -> manager mutation is existing ordering. No controller/manager/data-call locks or timer in_flight lease span dialog or file I/O.

Only one physical file picker globally at a time, including an old session's still-open native picker. A dedicated RAII permit prevents overlapping dialogs; a physical document marker outside replaceable WindowState suppresses only automatic blur hide for the owning document until its native dialog settles, even if a new session reuses that document. Logical result authority remains bound to the old exact session and expires immediately on replacement. Both should_hide_on_blur and begin_document_hide(only_if_blurred) honor marker. Explicit close/hide/removal, new submit, revocation, reload and shutdown remain nonblocking and invalidate result authority. Never use timer in_flight to wait for user dismissal; don't block these operations on a native dialog. Move the RAII permit into the blocking closure so async task cancellation cannot release it before native work exits. Drop cleanup must only clear its own physical token/document marker and release global permit, never mutate a newer session.

The native adapter uses existing tauri-plugin-dialog with actual plugin shell as parent, fixed title `选择文本文件（最多 8 KiB）`, one file, text extensions json/txt/md/csv plus All files if supported. No arbitrary title/filter/default path input. Run native blocking work off UI thread. Recheck ownership/grant immediately before adapter start, after selection before read, and on final result delivery under controller+manager checks. Cancellation/parse/error results also must not publish to a stale session. Closing/removing parent may dismiss native dialog; if OS leaves it open, retain global permit until it settles and discard its result.

At normal picker completion, restore focus only to the same still-current visible authorized window, while its blur guard is retained; never show/focus a stale or replacement window or main launcher. Capture the original native shell handle at admission rather than resolving a replacement later by label. Clear guard after restoration. If focus restoration fails, report sanitized failure and reconcile existing auto-hide path instead of permanently suppressing blur. Don't change pin state or normal focus behavior. Keep explicit native effects outside mutex guards; rechecks/identity-bound operations prevent stale follow-up. Successful delivery is linearized at final authorization; subsequent lifecycle changes are handled by bootstrap ownership rejection.

## Bounded local read

No path is accepted from renderer; it originates only from native selection. Before opening, require absolute ordinary drive path, local fixed/removable drive, no UNC/device namespace, no ADS, no relative/dot traversal or reserved device components. Reject reparse points in selected path components, directories and nonregular targets. Use current Windows filesystem features to open readonly with no-follow final component; validate the opened handle is regular disk, not reparse, and its final resolved location is local (parent substitution must not bypass locality). Read at most8193 bytes from that same handle; reject above8192, decode strict UTF-8, allow optional leading UTF-8 BOM, reject NUL. Metadata size is an early check, never sole size enforcement. No writes, no persistent grant/handle, no enumeration; handles close on all paths. Local-file tests use only generated temporary fixtures. Native dialog tests use a fake adapter.

## Existing JSON workbench

Keep pluginId, command identity, workbench.draft storage schema and revision logic. Upgrade example to1.1.0/minHost0.13.0 with files.openText. Add compact secondary button `导入文件` following UI guidelines and existing520x360 layout, accessible labels, theme tokens and keyboard order. UI exposes8KiB UTF-8 limit in concise help/error copy.

Click explicitly invokes captured files.openText outside onUpdate/Runtime request; never auto-opens on command/update. During import disable repeat business actions; input edits may continue and increment editRevision. A selected result can replace current editor only for same session/request/editRevision. If edits happen while choosing, retain them and show that import was ignored. On successful import clear formatted output, replace draft.text/input only, keep known savedText/revision/hasSaved/recovery semantics, mark unsaved and show basename with textContent. Do not autoformat, autosave, store filename/path or change original file. Existing storage-uncertain/recovery blocks must not be bypassed.

Before import when current draft is dirty, use the existing inline confirmation area to explain that a successful import replaces current input; cancellation/error keeps draft and formatted output. Confirmation cancellation doesn't open picker. Existing reload confirmation remains correct and changes back its button text/action. A subsequent user edit invalidates old authorization to replace draft. New onUpdate invalidates old import. Cancelling native picker is neutral feedback, not an error. Importing invalid JSON is allowed as text; existing format reports syntax error and explicit save still works.
