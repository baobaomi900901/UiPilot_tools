# UiPilot 内置截图方案（已确认）

日期：2026-10-29。用户已确认本方案，作为后续实施依据；确认设计不表示功能已经实现或验收通过。

## 1. 已确认需求与推荐结论

用户已确认首版包含区域选择、窗口选择、复制和保存；区域选择必须支持桌面自由框选，能够跨越多个窗口。

推荐：在 UiPilot 主程序中新增 Windows 截图模块，以 `rust_uia` 的截图实现为参考，采用原生截图选择层和宿主 React 预览窗口。首版不把完整 UIAutomation Provider EXE 作为运行依赖。

核心流程：启动截图 → 隐藏启动器 → 冻结可见桌面 → 框选区域或点选窗口 → 预览 → 复制 / 保存 PNG。

不包含标注、OCR、贴图、滚动长截图、录屏、截图历史管理和公共插件截图 API。窗口截图语义是“冻结桌面中该窗口矩形内的可见内容”；不承诺恢复被遮挡、最小化或屏幕之外的窗口内容。

## 3. 技术路线比较

| 路线 | 优点 | 代价与适用性 |
| --- | --- | --- |
| 直接打包现成 Provider EXE | 窗口内截图接入较快；已有取消和进程监控 | 当前能力不满足自由框选；额外产生 snapshot；引入管道、资产版本和自动化能力依赖。不能作为本次需求的完整方案 |
| 主程序内置专用截图模块，推荐 | 交互和生命周期归宿主管理；直接复用图片、剪贴板、主题；无需附带完整自动化服务 | 需要实现自由选区与多屏覆盖层，必须认真验收 DPI 和资源释放 |
| 新建精简截图 sidecar | 原生截图与宿主进程隔离；以后可独立演进采集后端 | 同样需要实现自由框选，还增加协议、构建分发和进程清理。首版收益不足 |

推荐路线保留清晰的采集接口。如果后续确有驱动兼容或故障隔离需求，可把采集实现移到精简 sidecar；首版不预先搭建跨进程框架。

## 4. 用户交互

### 4.1 入口与收藏

- 新增内置命令 `/screenshot`，可通过“截图 / screenshot”搜索；默认 Enter 开始区域截图。
- Ctrl+K 动作菜单提供“区域截图”和“窗口截图”。输入命令本身只展示入口，不因搜索或补全自动截图。
- 作为可重复使用的启动器入口，支持右键收藏、取消收藏及收藏列表执行。
- 完整贯通 Rust `BuiltinFeature`、`ResultFavorite::builtin(...)`、前端类型、`safeResultFavorite`、`favoriteMatchesResult` 和上下文菜单测试。
- “设置 → 通用”增加紧凑的截图快捷键设置行；初始不注册快捷键，用户可录制或清除。配置后直接开始区域截图。

### 4.2 选择

- 开始前记录触发来源和原前台窗口，隐藏主启动器及本次截图自身 UI；其他应用保持原状。
- 等待隐藏被桌面合成反映后采集桌面，再显示覆盖层。不能用单个固定 sleep 作为“启动器已从截图消失”的唯一保证。
- 区域模式允许任意方向拖动，跨窗口、跨显示器选区；显示真实输出像素尺寸。零面积选择不提交，保持可重选状态。
- 窗口模式使用冻结时的可见顶层窗口矩形和层级快照，悬停显示边框，单击确认；不调用 UIA 或 DOM 指认，不恢复或激活目标窗口。
- 窗口内容来自同一冻结画面，因此遮挡物会保留；屏幕外部分被裁掉。冻结后不再混入新时刻的画面。
- Esc 取消本次选择；覆盖层销毁并释放输入捕获。由启动器发起则恢复原查询和焦点，由全局快捷键发起则不额外弹出启动器。
- 区域模式提供键盘十字光标：方向键移动 1 物理像素，Shift+方向键移动 10 像素，Space 设定起点，Enter 提交非空矩形。窗口模式方向键切换候选，Enter 确认。

### 4.3 预览与输出

- 选择完成后退出全屏覆盖层，打开宿主拥有的截图预览窗口。
- 采用 44px 标题栏、48px 紧凑工具栏和图片预览区；显示尺寸，提供“重新截图”“复制”“保存”。不加入管理侧栏或介绍卡片。
- 首版预览不增加图钉，避免把临时预览演变为贴图功能。
- Ctrl+C 复制图片，Ctrl+S 打开保存对话框；Tab 可遍历动作，Esc 或关闭按钮结束会话。保存对话框内的 Esc 只取消对话框。
- 复制成功后保留预览，以便继续保存；保存成功也保留预览。仅显示成功提示，不重复弹窗。
- 保存使用系统对话框，PNG 文件名建议为 `截图_YYYY-MM-DD_HH-mm-ss.png`；目标存在时按对话框确认覆盖。取消保存保留预览。
- “重新截图”以同一模式重拍；旧预览结果保留到新选择完成，新选择取消则返回旧预览，避免丢失尚未输出的图片。
- 所有工具控件遵守 `docs/ui-guidelines.md`：双主题、宿主 token、Lucide 图标、可访问名称、稳定焦点与尺寸。原生选择层需要接收同一主题的语义颜色，不另设一套任意配色。

## 5. 模块与数据流

建议新增 `src-tauri/src/screenshot/`，内部按责任划分：

| 模块 | 责任 |
| --- | --- |
| `service.rs` | 单会话协调、触发来源、状态转换、取消与晚到结果丢弃 |
| `model.rs` / `geometry.rs` | 物理坐标矩形、显示器布局、选区归一化与裁剪，纯逻辑可测试 |
| `windows/capture.rs` | 可见桌面采集、GDI 资源管理、像素格式与显示器快照 |
| `windows/overlay.rs` | 原生覆盖层、鼠标/键盘选择、窗口候选命中、输入捕获和释放 |
| `output.rs` | PNG 编码、调用共享剪贴板写入、用户确认的文件输出 |

前端新增截图预览组件和对应 Tauri client 接口；与主启动器通过现有宿主窗口管理方式连接。新增窗口同步纳入主题、刷新快捷键拦截和窗口关闭处理。

数据流：启动器 / 原生快捷键 → ScreenshotService → 桌面帧与显示器布局 → 原生选区 → 后端裁剪结果 → 宿主预览 → 剪贴板 / 用户选定文件。

像素和最终 PNG 由 Rust 保管，前端只接收会话身份、尺寸和预览访问凭据。预览通过受窗口与会话约束的内存资源读取，不通过 JSON/base64 反复传输大图，也不向前端开放任意文件读取。

建议内部操作为 `start(mode)`、`copy(sessionId)`、`save(sessionId)`、`retake(sessionId)`、`close(sessionId)`；这是新增宿主接口设计，不是参考 EXE 已提供的合同。保存位置由宿主打开的系统对话框取得。

开始操作只接受受信任的主窗口或宿主原生快捷键；输出操作只接受当前截图预览窗口和有效会话。公共插件窗口不能调用。每个异步回调都要核验会话代际，旧结果不能覆盖新会话。

## 6. 关键实现约束

### 6.1 坐标和图像

- 后端统一使用有符号物理屏幕坐标；负坐标显示器是正常情况。矩形采用半开区间，拖动方向不影响结果。
- 选择层建议每个显示器建立一个原生无边框覆盖窗口，共享一个全局物理选区；不使用一个 WebView 横跨混合 DPI 的全部显示器。
- 位图按物理像素裁剪，预览 CSS 缩放仅影响显示，不改变最终输出尺寸。
- 跨屏输出按物理桌面布局拼接；无显示器覆盖的间隙使用不透明黑色，不拉伸任何屏幕内容。多显示器采集为逐屏快照，不承诺硬件级同时取帧。
- 显示器断开、布局或 DPI 在选择期间变化，取消该选择并提示重试；不使用旧坐标继续裁剪。
- 可见桌面捕获可从 GDI 路径起步，必须在真实机器验证分层窗口、WebView2、不同显卡和 HDR。正确性未达标的场景不直接宣称支持。
- 不把纯黑、纯白或低方差内容判为截图失败：用户可能正要截图空白画布。参考项目针对 PrintWindow 的启发式不适合直接用于自由截图。
- 首版输出 8 位 PNG；不承诺 HDR 原始色彩保真，也不包含鼠标指针。受系统保护的画面不尝试绕过限制。
- 采集和编码不占用主 UI 线程；原生覆盖层由专用消息循环管理。位图尺寸乘法、分配与裁剪必须做边界检查，并配置明确的像素/内存上限。

### 6.2 生命周期

状态主线：`Idle → Preparing → Selecting → Preview → Copying/Saving → Preview → Idle`。

- 全进程只有一个截图会话。Selecting 时重复触发不新增覆盖层；Preview 时重复触发聚焦已有预览，需要重拍时使用明确动作。
- Copying/Saving 期间禁用重复输出和重拍；复制/保存完成后再执行已请求的窗口关闭，避免释放仍被使用的数据。
- 正在重拍时保留旧结果，在新结果成功时替换；取消重拍则回到旧 Preview。
- 退出、锁屏/会话切换、显示配置变化均必须结束原生选择、释放鼠标捕获和 GDI 资源；进程退出时不残留覆盖层。
- 焦点恢复核验旧窗口仍存在且当前前台仍由本截图流程拥有，避免覆盖用户已经进行的新切换。
- 选择层覆盖期间，主启动器热键和插件快捷键不应再打开窗口破坏截图；由生命周期协调器暂缓这类显示请求，结束后不自动回放过期命令。

### 6.3 剪贴板和保存

- 当前 `clipboard_history/paste.rs` 已有 PNG、DIBV5、DIB 多格式写入逻辑，但接口绑定历史记录，不能直接假设存在通用 `copy_png`。
- 提取可共享的图片剪贴板写入函数，供历史记录与截图共同调用；截图不伪造历史记录，也不发送 Ctrl+V。
- 历史记录服务按自身启用状态观察剪贴板，不再额外手动插入一份截图记录。
- 剪贴板占用时做有界重试；失败保留预览并允许再试。写入返回真实结果，不把部分格式失败隐藏为完整成功。
- 完整 PNG 编码通过后才修改剪贴板或提交文件。保存使用目标目录内临时文件和原子提交，失败不破坏已有目标文件，尽力清理本次临时文件。
- 默认不自动落盘、不上传。预览关闭释放会话数据；日志只记录尺寸、耗时和错误类别，不记录图像内容。

### 6.4 快捷键

- 当前 `CommandEntry` 和设置映射面向 `pluginId + commandId`；内置截图不得伪装成公共插件 ID。
- 新增宿主截图快捷键设置和独立注册状态，复用 `LifecycleCoordinator` 现有操作串行门、录制控件及回滚模式。
- 与主启动器及所有已保存插件命令快捷键做双向冲突检查；系统注册失败给出可重试状态。
- 不把截图快捷键塞进 launcher-only 的 `RuntimeSettings.registered`，避免现有回滚逻辑误卸载。
- 录制期间只录键，不截图；注册事件校验当前绑定代际，忽略按键重复和失效回调。

## 7. 交付阶段

1. **验证截图核心**：先验证混合 DPI/负坐标、多屏冻结、自由框选、顶层窗口候选及退出清理。使用可控测试画面检查真实像素；此阶段解决采集后端是否满足首版的主要不确定性。
2. **完成用户闭环**：接入 `/screenshot`、原生选择、预览、复制、保存、取消和重拍，保证一次完整截图可用。
3. **完善宿主集成**：收藏全链路、可配置快捷键、冲突回滚、双主题、键盘无障碍、窗口权限及生命周期联动。
4. **发布验收**：真实 Release 宿主验证显示器矩阵、典型应用粘贴、安装后启动与连续截图资源稳定性。

这些是交付顺序，不是已经批准的实施计划。后续实施计划应遵守仓库 `docs/agents/implementation-plan-guidelines.md`，无需在各任务重复本文技术合同。

## 8. 验收标准

自动化验证聚焦纯几何、单会话状态、输出和宿主入口：

- 四种拖动方向、负坐标、跨屏、零面积、越界裁剪和尺寸溢出。
- 重复触发、取消、取消重拍、过期回调、退出清理和输出过程中关闭。
- PNG 编码与剪贴板三个格式、占用失败重试、保存取消/失败以及覆盖文件的安全提交。
- 收藏协议和菜单；快捷键冲突双向检查、录制抑制、持久化失败回滚。
- 非宿主窗口及失效会话不能读取、复制或保存截图；预览键盘和双主题状态。

人工验收必须使用真实宿主编译物：

- 100% / 125% / 150% / 200% 缩放，混合 DPI，副屏位于左侧或上方，横竖屏及跨屏选区。
- 跨两个应用窗口自由框选；点选顶层窗口；结果不包含本次启动器、覆盖边框和预览窗口。
- 白色/黑色纯色画布、浏览器/WebView2、透明或分层窗口、HDR 开关场景。记录支持边界而不是用启发式静默换图。
- 图片粘贴到画图、办公编辑器和聊天输入框，确认尺寸、颜色和格式兼容。
- 锁屏、显示器断开、截图中退出、保存失败、快捷键冲突，均不残留覆盖层或输入捕获。
- 连续截图并关闭 50 次，观察 GDI 句柄和内存是否持续增长。
