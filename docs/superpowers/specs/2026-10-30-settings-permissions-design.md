# 设置权限页设计

日期：2026-10-30
状态：用户已确认并要求继续实施；按权限分类组织。

## 目标与范围

在设置左侧“插件”之后增加“权限” tab，集中管理已安装公开插件申报的权限，包括网络。复用宿主现有 React、Ant Design、Lucide 和主题 token，遵循 docs/ui-guidelines.md。保留已有插件页面与详情结构，不改 rust_uia。

## 页面

- 页头“权限”、分隔线、搜索输入框；搜索匹配插件名称、启动命令与权限名称，Ctrl+F 聚焦当前页搜索框。
- 按网络、剪贴板、文件访问、界面、通知、计时器、后台运行分类，以分组标题及紧凑列表呈现；只显示有插件申报的分类。
- 每行：插件图标、插件名称、具体权限名称/简短用途、授权状态与开关。一个插件的不同能力分别成行，例如剪贴板历史读取和历史粘贴互不代替，不提供隐式联动的分类总开关。
- 仅列出插件实际申报的权限。宿主未支持的申报能力显示“不支持”并禁用开关。
- 插件已停用时仍可管理已保存授权；注明插件已停用，改变授权不会启用插件。
- 网络行可展开申报的 HTTPS Host 和凭据绑定范围；显示绑定名称与目标，不显示密钥。
- 无插件、无申报权限、搜索无结果及加载失败分别显示简洁稳定的空状态/错误及合适的刷新入口。
- 宿主内置功能及旧版兼容插件未使用公开插件授权模型，不伪造可控权限。必要时在页尾用简短说明标注其不受本页管理。

## 开关行为

- 点击后保存，等待宿主结果与权威清单回读后显示最终状态；同一插件的变更串行，处理中禁用该插件相关开关。失败行内显示原因和刷新入口，不自动重试写入。
- 开启网络沿用现有 Host 和凭据绑定确认，取消不写入，确认时核验清单版本，范围变化要求刷新后重新确认。网络关闭沿用现有撤销与请求退役逻辑。
- 普通权限直接切换，不额外增加通用确认弹窗；仅修改该项，不隐式授予依赖权限。
- 权限撤销必须由宿主执行：之后的能力调用及结果动作重新校验授权；必要时撤销已有会话/结果/请求，不能仅改 UI。已经完成的系统操作无法撤回。
- 关闭界面权限会关闭受影响的插件面板/窗口；界面行说明这一效果。关闭计时器或通知权限按现有资源归属清理相关活动资源，防止旧任务继续使用被撤销能力。
- 权限配置重启后保留；重新加载或更新不能静默恢复用户关闭的、仍然申报的权限。新增权限仍经过现有安装/更新确认流程。插件停用、命令名和快捷键不因授权变更而被改写。
- 插件详情页权限状态及既有网络开关与此页使用同一宿主状态和变更通知，避免两份独立配置。

## 宿主与数据边界

现有网络有管理接口；普通权限目前仅有安装授权和清单展示，本次补充统一的安装后授权/撤销接口。网络继续复用其专门的范围校验和撤销流程。

管理 IPC 仅允许主 WebView 调用；校验插件仍安装、权限已申报且受当前平台支持、清单版本有效。插件自身不能为自己授权。持久化与运行时权限发布遵循已有管理事务、资源退役、失败关闭和清单版本规则；不将权限开关简化为直接写配置集合。

安装、恢复及更新状态校验调整为允许合法的部分授权，拒绝未申报权限。保留旧设置兼容。对每个现有受支持权限核对调用和长生命周期资源的撤销边界，未明确完成宿主约束的能力不可展示为已成功撤销。

## 验证

- 分类、搜索、同插件多权限、停用插件、未支持权限、空/错误状态和键盘操作。
- 逐项授权/撤销、网络确认取消及范围变化、写入失败回读、重复点击和旧异步响应。
- 宿主拒绝非主窗口、自我授权、未申报/未支持权限与过期清单。
- 关闭后能力调用/旧结果/面板窗口/网络请求/活动资源不可越过授权；互不相关权限保留。
- 重启、重新载入及更新保留用户撤销，新增权限仍确认。
- 前端构建与相关测试、Rust 定向测试；深浅主题及窄窗口实际渲染。

## 方案取舍

采用用户选择的“按权限分类”列表，便于比较各插件对同类能力的使用。按插件分组更适合逐个审查但不采用；插件×权限矩阵在窄设置窗口中需要横向滚动且难以解释细分能力，因此不采用。
