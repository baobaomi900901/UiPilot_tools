# 翻译插件使用宿主密钥与独立授权

## 目标

保持插件 ID `com.uipilot.translate` 和启动指令 `/translate`，将显示名称改为“翻译”。插件详情展示对有道翻译、百度 OCR、DeepSeek 三项宿主密钥服务的申请和授权状态；设置权限页增加对应的独立授权分组。

当前插件使用包内旧测试凭据。新密钥管理与已有插件私有 Bearer 凭据是两套存储，不能把已有 network.credentials 当作已接入宿主配置。用户本次明确要求同时修改宿主授权页面，因此本任务包含宿主、SDK 与插件包的联动修改。

## 推荐范围

用户已选择推荐范围：本轮先把已有有道中英互译迁移到宿主密钥，保留提交后翻译、Enter 复制的交互；建立三项服务的申报与授权。百度 OCR 与 DeepSeek 的翻译界面和业务流程后续实现，不因授予权限而发送请求。

## 方案比较

1. **宿主代调用（推荐）**：插件提交业务输入，主程序检查授权、取用密钥、完成签名并请求固定服务，只返回所需业务结果。可撤销使用权，插件无需持有密钥。
2. 返回密钥明文给插件：改造较少，但插件能够保存或转发凭据，撤销权限也无法收回已经读取的密钥，不采用。
3. 将宿主配置复制到插件私有配置：可复用部分存储，但更新与删除不一致、有道签名仍需新增能力，不采用。

## 权限及页面

- 新增服务级权限：`credentials.youdaoTranslation`、`credentials.baiduOcr`、`credentials.deepseek`，分别表示使用对应宿主服务，不代表读取明文。
- Manifest 必须明确申报；插件详情“主程序密钥”区显示服务名称、配置可用状态、授权开关。设置权限页显示三个中英标题分组，行保持“图标 | 插件名称 | 开关”。两处操作同一份持久化授权。
- 分组标题：有道翻译密钥 / Youdao Translation；百度 OCR 密钥 / Baidu OCR；DeepSeek 密钥 / DeepSeek。
- 未申报不能授权。新增授权默认关闭，不能因旧网络授权、安装更新或密钥已配置而自动打开。用户可逐项授权，无需开启当前未使用的 OCR 或 DeepSeek。
- 有效调用同时要求：插件启用、服务已申报并授权、全局配置已验证且启用、网络权限已开启并覆盖对应固定主机。
- 全局密钥开关与插件授权分开显示。插件授权已开但全局配置关闭时，显示“配置已关闭”；没有配置时显示“尚未配置”，不得误写成“未授权”。
- 开启服务授权时明确说明允许该插件使用此服务及可能消耗 API 额度。不会自动替用户打开开关，也不自动修改真实密钥。

## 宿主边界

- 本轮提供有道翻译的请求绑定接口，接收文本与语言方向，不接受 URL、任意请求头、签名模板或密钥字段。OCR 和 DeepSeek 权限只先管理授权，不暴露尚未实现的调用方法。
- 首版业务接口仅支持当前翻译插件使用的旧式 `command + mainResult`，且 `runtime.resultActions` 未启用。其他 Windows 插件形态可以申报和管理服务授权，但调用该方法会被宿主拒绝；不因存在 facade 推断授权或兼容性。扩展到 Panel、Window 或结果动作时必须补齐各自最终发布阶段的权限检查。
- 有道签名和请求由宿主处理，固定 HTTPS 目标，禁止重定向。沿用现有请求上下文的超时、大小限制、频率限制与调用者检查。
- 返回规范化译文及静态错误码，不返回原始认证请求、密钥、供应商原始响应或 OAuth token。不增加密钥 getter。
- 每次调用独立检查当前授权与配置。权限撤销、插件关闭/重载、密钥关闭/删除/替换时使旧调用上下文失效，阻止晚到结果发布；已发出的远端请求不能保证撤回，不自动重试。
- 主程序携带不可由插件伪造的服务调用版本，直到最终结果注册发布时再次检查；测试覆盖请求已完成但前端查询尚未注册结果期间的密钥变更。被拒绝的过期请求不能覆盖当前有效请求的撤销记录。
- 三项服务授权必须独立持久化并经过 Manifest、SDK 类型、Schema、CLI 及前端 DTO 校验。旧配置迁移保留原授权，新增权限不默认授予。
- 删去插件包内旧测试凭据与签名逻辑，更新名称、版本、最低宿主版本、文档与测试。保持插件 ID，避免丢失现有启动命令配置。

## 错误与验收

- 明确区分：未授权服务、密钥未配置、配置已关闭、网络已关闭、供应商拒绝、额度/限流、请求过期。提示指向正确设置页，所有状态使用应用内反馈。
- 离线测试覆盖三项授权独立启停、旧授权不升级、未申报拒绝、错误状态、配置变更使旧调用失效，以及翻译结果复制。
- 复核插件详情与权限页切换后的状态一致性；深浅主题、窄窗口、键盘及取消授权对话框行为保持现有 UI 规范。
- 不读取或输出用户的真实密钥；不使用真实 API 做自动化测试。真实有道调用由用户在更新后的插件中手动验收。
