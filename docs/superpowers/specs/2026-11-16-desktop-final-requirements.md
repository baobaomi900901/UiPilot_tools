# UiPilot Windows 与 macOS 最终需求

日期：2026-11-16。依据用户已确认的完整目标及最新 main 功能更新范围；这是最终产品需求与完成判据，不代表实现或发布已经完成。实现细节继续以具体能力设计和 SDK 合同为准，后续 Mac 平台扩展不得静默放宽安全边界。

## 1. 目标与代码基线

用户能在 Windows x64 与 Apple Silicon Mac 使用同类启动器、常用系统工具及主要插件。共同能力的命令、参数、数据、结果与授权失败语义大致一致；插件作者尽可能维护一套源码、Manifest 和归档，两端按相同公开合同工作。无需复制 Windows 内部机制、界面上的 Ctrl 字样或平台独有组件。

Windows 新基线为本地 main = origin/main = `bccecb134ed06e9692a8322be9d8a9b39e03c4a3`，Host 0.22.0 / API、schema 1；本地 main 工作树已于本日从 40407fa 快进更新。macOS 开发分支仍为独立 `codex/macos-port-plan`，未合入此主线，其已验收包仍为 0.19.0。新版本号、下载代码或自动合并不能充当新能力可用证据。

用户本次明确要求**暂不把 main 合入 macOS 分支**。当前只更新本地 main、最终需求和计划；后续合并需要用户解除此暂缓要求。macOS 成果仍不并入 main，除非用户另行明确授权。需求文档和计划提交在 macOS 分支，不改 main 的上游提交。

## 2. 双平台最终能力矩阵

| 编号 | 两端最终用户需求 | 平台差异及当前证据边界 |
| --- | --- | --- |
| R1 启动器 | 单实例、托盘/菜单栏唤起与退出；中文/英文应用搜索、打开或尽力激活；焦点可直接输入；IME 确认不误执行；隐藏再现与多屏位置正确 | Windows 开始菜单/AUMID 与 Mac 应用包发现分别实现；Windows Ctrl，Mac ⌘；用户自录全局快捷键原样保留 |
| R2 设置与交互 | 主题、图钉、键盘操作菜单、滚动/拖动、底栏左侧统一提示；普通快捷键及可选双击修饰键、登录启动、命令配置和收藏 | 原生授权/系统登录项不同。拒绝或撤权必须显示不可用及当前生效/回退状态，保存失败保留原配置；Mac 登录项专项人工按用户要求暂不继续 |
| R3 文件搜索 | 独立 Find、分类、当前文件信息与图片预览、定位选中项；再次打开无参数保留搜索，有参数更新；停止授权后清除结果/预览和旧动作 | Windows 保留 Everything/SystemIndex；Mac 默认系统已索引且可访问的本地文件，文稿按系统授权扩大范围并可记住/忘记；不要求搜索未索引或不可读文件，不偷偷全盘扫描 |
| R4 常用内置功能 | 计算、单位、日期/时区、汇率及复制；网页搜索引擎选择、快速链接创建/编辑与参数编码；可复用入口可收藏，提供相应启停和命令管理 | Mac 当前已接入多数基础功能，汇率离线实机仍待确认；内置启停已验收，完整命令改名/快捷键还需对齐。Windows 浏览器选择与搜索引擎概念分开 |
| R5 插件管理和 Runtime | 安装/卸载、兼容升级、启停、改名/收藏、普通设置/存储、权限配置与恢复；mainResult、Panel、Window 按各自能力可运行 | Mac 管理已实测，生产 Runtime 仍关闭；隐藏执行环境、内容页来源、私有 RPC、隔离、恢复均须满足原合同再开放。不得用修改平台声明替代实现 |
| R6 插件系统服务 | 受控 HTTPS、宿主凭据与插件 secret、剪贴板历史与复制、受控粘贴/选区、通知/计时、语音等参考插件实际需要的能力 | 按公开 SDK 最小权限逐项移植，DPAPI/Windows 与 Keychain/Mac 内部实现不同。显式用户动作、撤权失效、外部剪贴板保护与有界存储不能丢失；无凭据明文下发 |
| R7 图片输入与 OCR | 主输入显式粘图后按声明列出兼容 OCR；先粘图或先 `/ocr` 进入同一左右 Panel；预览、编辑完整文字、清图/换图、重试和复制 | 以 main 的最终 OCR Panel 设计为准，初版旧 mainResult 图片协议继续兼容；不恢复旧的专门优先某插件 ID 行为。Mac 要补原生读取、Panel 及百度服务接线 |
| R8 文本分享 | 操作菜单分享当前编辑全文，用户选兼容目标；OCR→翻译只接收/处理一次；接收插件可只保留草稿；译文可再次分享 | 单一活动 Panel，仅 text/plain；Windows Ctrl+K / Mac ⌘K。选择前取消保留来源，选目标后加载/接收/业务错误留在目标，不自动回源或重发 |
| R9 其他原生工具 | 原计划内的截图/多屏输出、通知、选区/粘贴、系统集成及进程工具按可证明权限范围实现 | Windows Provider/提升 Helper、Everything、WebView2/NSIS 为平台实现细节，不搬到 Mac。Mac 截图/输入等受系统授权；不把不安全或无法等价的进程操作默默开放 |
| R10 交付与升级 | Windows setup 和 Mac arm64 DMG，正常安装/启动/退出；升级保留设置、命令/收藏、数据及已撤销权限；卸载和恢复规则明确 | Mac 当前最低 15.7.4、M1 实机；后续芯片/较新系统按用户要求跳过且标记未测。公开分发另验签名/公证；无 Apple 证书时只交内部测试包 |

以上是最终目标，不等于现有全部 SDK 限制要同时取消；能力按完整包校验，平台专用能力单列并解释原因。普通插件只依赖共同能力时，不应被迫维护两个业务分支。旧插件另做迁移与安全兼容评估，不无条件承诺历史私有 API 在两端照搬。

## 3. 新增图片与分享合同

main 的详细合同从本地 main 工作树读取：

- `docs/superpowers/specs/2026-11-06-ocr-panel-design.md` 的“两种入口”“新增公开桥合同”“异步与失败行为”是最终 OCR 行为；覆盖早期 mainResult 方案的交互选择，保留旧协议兼容。
- `docs/superpowers/specs/2026-11-06-plugin-sharing-design.md` 的“边界与失败行为”“宿主流程”“调用与数据边界”是最终分享方案；旧双面板回滚、复杂分享准备事务不再作为目标。
- `docs/plugin-sdk/public-plugin-v1.md`、API 类型、Schema 及 CLI 校验必须一致；Windows-only 限制在 Mac 实现/验证前保持原声明。Mac 扩展设计单独补充。

R7 必须满足：只在明确粘贴动作读取当次图片；有界解码和预览，标准化快照与识别图一致；无图不识别，选中列表项不识别，进入有图 Panel 后自动一次；清图不请求；换图 A→B→C 仅最新图可发布，坏图不替换原有效图；复制为用户编辑后的全文，超限明确失败而不截断；隐藏、撤权、更新或凭据变化后旧请求不能发布/复制。图片和识别正文不新增永久历史、日志副本，不调用真实服务做自动测试。

R8 必须满足：按声明发现接收者、不执行候选 Runtime、不硬编码 OCR/翻译 ID；正文保留空格/换行，按 UTF-8 和目标预算拒绝超限，不静默截断；来源快照、目标文档和会话精确绑定，重复通知/Enter/claim 不重复交付。正文只走私有定向通道，不经过通用事件总线、launcher query/history 或剪贴板历史；不自动改写剪贴板。失败由目标明确显示，允许用户重新发起新操作而不复活旧未知会话。

## 4. 当前插件集合与兼容判据

main 的当前集合仍为 17 包，但旧 `com.uipilot.note` 已从仓库移除并新增 `com.uipilot.ocr`。`com.uipilot.notes` 继续维护。3 包声明双平台、14 包仅 Windows；双端生产宿主同包实测仍为 **0/17**。

- 先验 `demo-settings`、`demo-return`、`demo-multi` 的运行、数据、权限撤回与恢复。
- Panel/Window 与服务用 notes、clipboard-history、pomodoro、translate、ocr 等业务插件以及基座参考和聚焦 Demo 分层验证。
- OCR 当前 1.1.0、翻译 1.5.0，最低 Host 0.22.0，均仅声明 Windows；仅当完整必需能力可用并通过合同校验才扩平台。
- auth-check/json-workbench/templates 的目录改为 demo 前缀，pluginId 不变；旧归档和用户安装数据不因仓库整理被自动删除/授权迁移。

“同包通过”必须绑定相同版本/归档 SHA-256、两个宿主版本、设备、主要用户任务和拒绝/撤权行为。CLI 校验、内部运行器及假服务通过分别记证据，不算生产插件已可运行；主线文档中仍待人工的项不能继承为本分支已通过。

## 5. 完成门槛与测试负担

1. 功能门槛：R1–R10 的共同核心有两端实现，平台差异和保留项明确，无静默的功能消失/权限恢复或数据丢失。
2. 插件门槛：当前参考集合逐包有状态与原因；可移植共同能力包在两端完成主要任务，原生服务有授权/撤权/失败证据。平台专用/历史插件单列，不能为提高百分比随意从目标移除。
3. 工程门槛：Windows 原生构建/安装链、Mac default/preview 构建、SDK/CLI/生成物和相关回归通过；共享改动不能破坏 Windows。升级测试覆盖 0.19→0.22 的插件配置及状态保留。
4. 安全与分发门槛：当前调用来源、会话/代际、内容隔离、网络和凭据边界通过。Mac 无证书不阻断纯开发和内部包准备，但严格生产隔离、Developer ID/公证、Gatekeeper 发布验收保持待办；不借此提前宣布总目标完成。
5. 人工门槛：禁止 computer use，所有 GUI 由用户操作；仅在新行为或原生风险节点通知，一次一个动作，同类检查合并。新链路优先一次完成“粘图→OCR→编辑→分享→翻译→复制”，不重复既有快速链接/图标等步骤。浅色人工暂缓、较新 Mac 行跳过；这些是明确例外而非伪记通过。

总进度按工程实现、自动证据和人工/发布门槛评估，先前约 80% 只属于旧 0.19 范围。0.22 已加入最终分母，当前不给未经差距拆分的新百分比。开发和证书独立项、证书阻塞项分别报告，不把“无证书开发完成”等同总目标完成。
