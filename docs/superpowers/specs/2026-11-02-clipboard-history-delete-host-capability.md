# 剪贴板历史 Delete 按键：宿主能力请求

日期：2026-11-02

## 用户需求与插件场景

将 `com.uipilot.clipboard-history` 升级到当前公开插件规范，并在宿主 Ctrl+K 动作面板注册分类切换和删除当前记录：Tab 下一分类、Shift+Tab 上一分类、Delete 删除所选记录。继续保留方向键选择、Enter 粘贴、鼠标删除和清空历史。

插件现有 `panel.hostKeyFocus: "host"` 使键盘焦点保留在主输入框。Tab 等声明过的按键由宿主转发，插件内容页面不能直接监听主输入框的 Delete。

## 当前 API 缺口

- `panel.hostKeys` 白名单只有 ArrowDown、ArrowUp、Primary+N、Tab、Shift+Tab、Enter；SDK 的 `PluginPanelHostKey` 也没有 Delete。
- `onActions` 的 `shortcut` 是展示文字，并不注册实际快捷键。仅加入 `shortcut: "Delete"` 会造成菜单提示与真实行为不一致。
- `clipboardHistory.remove({ id })` 已支持删除；缺少的是合法、受会话约束的按键投递，不需要新增删除接口或扩大剪贴板权限。
- 不应通过改变 `hostKeyFocus` 绕过此缺口，避免破坏现有输入焦点和 Enter 粘贴的 routeSequence 安全协议。

## 宿主/API 行为（已获用户授权）

1. 为 Panel manifest 和 SDK 增加可选的 Delete host key，贯通 schema、CLI 校验、宿主解析、前端路由和原生桥接。未声明 Delete 的插件行为不变。
2. 仅当当前 Panel 声明 Delete、主输入框为空、未进行 IME 输入且没有修饰键时转发。输入框有文字时保留原生文本编辑行为，不删除历史记录。
3. 忽略长按重复 Delete，避免一次长按连续删除多条。Ctrl+K 菜单拥有焦点时由菜单处理输入，不向背后列表投递。
4. 复用现有 sessionEpoch、routeSequence、串行投递、ack 和失效会话处理；Delete 不产生 Enter 粘贴授权。版本门槛为当前开发中的 Host 0.16.0，同步更新契约、验证器和插件最低版本。

## 插件侧配套方案

- 使用 `onActions` 提供全局分类切换动作，以及针对所选条目的删除动作；无选中项或删除进行中时显示禁用原因。
- 动作菜单、鼠标删除和键盘删除复用同一函数；回调执行前核对会话、所选 ID 和记录是否存在。重复请求、过期回调不得删除其他记录。
- 使用宿主 `setStatus` 显示成功、失败和读取异常，移除插件内容区重复状态；保持宿主右侧 Ctrl+K 入口。
- 保留现有分类、虚拟滚动条、主题和粘贴协议，不读取额外剪贴板格式，不增加权限。
- 更新包版本、最低宿主版本、README、SDK 类型测试及独立预览；预览和自动化只使用合成记录。

## 验收

- Tab/Shift+Tab 在全部、图片、文件、文本之间循环，动作菜单执行结果与快捷键一致。
- 空主输入框中单次 Delete 只删除当前记录；文本输入、IME、修饰键、长按和菜单打开场景不误删。
- 菜单打开后记录/会话变更，旧删除回调不能删除新选择；删除失败仍保留列表，并在宿主状态栏显示固定错误文案。
- 无记录时删除禁用；删除后按快照协调选择，不伪造本地成功状态。
- Enter 仍只使用真实宿主路由序号粘贴，Tab 和方向键不改变原有焦点策略。
- 插件 Node 测试、SDK 类型检查、包校验通过；宿主补充 manifest、桥接和路由回归测试。

## 交付边界

依据仓库 AGENTS.md 的公开插件开发边界，本请求先交给宿主开发。获得明确的宿主开发任务授权之前，不修改 `src/`、`src-tauri/`、`packages/plugin-cli/` 或 SDK 契约来补齐此能力。
