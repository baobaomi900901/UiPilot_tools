# Mac 已可用内置功能的启用管理

补齐原移植计划的设置与能力一致性：Mac「设置 → 插件」列表增加独立的「内置功能」分组，管理网页搜索和快速链接。它们是宿主已经开放的能力；公开插件 Runtime 状态不变。现有命令、收藏和管理内容保留，暂不增加内置命令改名/独立快捷键，也不显示尚未开放的截图开关。

## 状态与 IPC

只读列表和启用写入使用新的 Mac main-only IPC，调用者和来源验证先于 SettingsStore 读取。严格枚举只有 webSearch / quicklinks，拒绝未知字段和未开放功能。返回固定名称/命令及当前启用状态。沿用 SettingsStore 原子持久化，状态写入失败不发布乐观成功，UI 要求刷新核对，不自动重试；数据目录和文件 IO 在 worker 执行。设置文件保留收藏、搜索引擎及快速链接配置。

停用网页搜索后，普通查询的搜索引擎行及 /web-search 入口均不发布。停用快速链接后，/quicklinks 与自定义命令均不发布，其读取/保存/图标选择接口继续使用现有 enabled gate。浏览器执行在最终准入时重新检查 enabled：停用先于准入则拒绝，准入先发生的请求可以完成但完成归属仍受原票据限制。Windows 路径与设置格式不变。

## UI 与操作生命周期

复用 Mac 插件列表的筛选框、开关、布局与宿主底栏左侧反馈。内置功能行显示名称、命令和状态；开关具有明确 aria-label。不伪装成已安装包，不显示插件暂不可运行状态。筛选命中内置项时不显示「没有匹配的插件」。公开插件详情/授权/安装流程保持原路径。

启用状态由已确认后端响应更新。页面共享 pending/generation 与跨挂载客户端操作队列：一次写入未完成时不允许第二次切换；新页面读必须排在旧页写入之后；旧页面返回不得覆盖新页。短暂保存期间使用 aria-disabled 保持原开关焦点，键盘和鼠标再次触发均由 pending 拒绝，不在完成后抢焦点。失败时进入待核对状态，只有显式刷新读到权威状态后才能继续修改。

## 验证

使用临时设置目录和 fake browser，不读取真实快捷链接或打开浏览器。验证重启保留、收藏/引擎保留、未知 feature 拒绝、停用与旧动作最终准入顺序；前端验证筛选、连续切换焦点、并发写入抑制、失败不乐观更新/不重试、跨页面读队列。ACL 测试验证来源和其他 webview 不获授权。实际开关、停用后搜索和重启由用户逐步验收；禁止 GUI 自动化，浅色人工验证按用户要求暂不安排。
