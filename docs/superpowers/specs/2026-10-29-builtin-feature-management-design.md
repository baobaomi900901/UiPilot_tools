# 设置插件列表中的内置功能管理

状态：用户已确认。范围仅为 `/screenshot`、`/quicklinks`、`/web-search`。

## 用户需求

三个宿主内置功能出现在“设置 → 插件”列表，与插件一样可以查看详情、关闭和重新启用，但不能删除。沿用现有列表和详情页的视觉、主题、键盘与返回行为。

## 推荐方式与替代方案

推荐在同一列表展示带“内置”标识的宿主条目，复用行布局与详情页外壳，由专用宿主接口读取和修改启用状态。它们不作为插件包注册，不进入插件卸载、权限或运行时逻辑。

其他方式：独立增加“内置功能”设置页，入口更分散；或把内置功能包装成插件包，涉及不必要的运行时和打包迁移。两者均不采用。

## 列表和详情

- 默认启用，内置条目固定在现有插件列表顶部，顺序为截图、快捷链接、网页搜索；参与现有名称、描述及命令搜索。停用后仍在设置列表中。
- 每行显示图标、名称、简述、命令、“内置”标识、启用开关和“详情”。没有删除、卸载、重新加载或安装按钮。
- 点击详情进入现有样式的详情页，显示功能说明、命令、使用示例、随主程序更新的版本信息、启用状态；返回按钮与 Esc 回到列表并恢复焦点。停用后详情仍可查看和重新启用。
- 命令名称固定，不添加命令改名、插件目录、插件权限、运行故障恢复等不适用操作。当前已有的通用设置保持原入口：截图快捷键与保存目录、默认网页搜索引擎不迁移。
- 深浅主题、开关成功色、加载中防重复提交和就地失败反馈遵循 `docs/ui-guidelines.md`。不发送系统通知。

## 关闭的具体含义

关闭是停用对应功能，不只是隐藏列表项；立即生效并跨重启保存。旧版本配置缺少该字段时三个功能全部启用。

| 功能 | 停用后的行为 | 保留内容 |
| --- | --- | --- |
| 截图 | 启动器不再推荐截图，手输命令、旧结果和截图快捷键均不能创建新截图会话 | 已保存的快捷键、默认目录、收藏、图片及已有独立贴图 |
| 快捷链接 | 不再推荐或打开管理入口，所有用户创建的快捷链接命令同时停用 | 链接模板、图标及收藏 |
| 网页搜索 | 命令和普通搜索结果中的网页搜索入口同时停用 | 默认搜索引擎及收藏 |

重新启用恢复入口及原配置。关闭不删除用户数据，不强制中断此前已进入的截图编辑或销毁贴图；旧快捷链接管理页不得在停用后继续发起管理写入或打开链接，可返回设置重新启用。已经交给浏览器的操作不撤回。

截图快捷键在关闭时注销但保留配置。重新启用时按既有冲突校验和注册回滚机制恢复；若原组合键已被占用，显示就地错误并保持关闭，不悄悄丢弃快捷键配置。停用期间修改或清除已保存快捷键也不能重新注册它。

停用的三个固定命令及已保存快捷链接名称仍保留名称占用，避免另一插件意外接管用户命令。`/find` 和其他内置计算功能保持当前行为，不纳入此次开关。

## 实现边界

- 增加仅包含这三个功能的宿主管理模型和持久化停用集合；与现有 `BuiltinFeature` 收藏身份映射。不能通过接口停用 `/find`，也不能将内置身份传入插件删除接口。
- 宿主提供内置列表、详情元数据和启停接口，调用授权沿用主窗口设置入口。公共插件清单与 SDK 合同不改变。
- 前端在设置列表合并两类展示条目，明确区分宿主功能与公共插件身份；复用通用布局，分别调用各自的管理接口。
- 后端在搜索发现和最终动作执行两处检查状态，包括快速链接展开、网页搜索兜底、截图命令和热键。状态变更刷新当前结果，已经显示的旧结果不能绕过停用检查。
- 设置写入和截图热键变更使用现有串行操作及回滚机制。持久化失败保持原有效状态；失败后读回权威状态再显示，不只乐观翻转 UI。
- 修改范围为主程序；继续使用原版 rust_uia 编译物，不修改该仓库。保留当前工作区的其他改动。

## 验证

覆盖三个条目的详情、启停、无删除操作、搜索过滤、深浅主题、键盘返回和失败回读；后端覆盖旧配置兼容、持久化、重新启用、旧结果拦截、快捷链接子命令及网页搜索兜底。截图热键覆盖注销、保留配置、冲突恢复和停用期间改键。回归原有插件安装、详情、启停、删除，以及截图功能。

人工验收：关闭各功能后测试命令和相关入口，重启验证状态；重新启用确认数据和设置保留。截图已有贴图应保持可操作。
