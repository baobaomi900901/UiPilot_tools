# macOS 剪贴板历史共用基础

本规格细化[移植计划 Task 10.1](../plans/2026-11-06-macos-port-steps.md#step-10)的首个代码单元。目标是让 Windows 和 macOS 使用同一套历史数据模型、格式优先级和预览规则，为后续原生采集与存储提供基础。本单元不开放 macOS 剪贴板历史，也不扩大公开插件 manifest 的平台或权限。

## 共享合同

复用 `clipboard_history/model.rs` 的捕获、摘要、历史文档和固定错误类型。摘要继续使用 camelCase 和既有 kind 标签；完整文本、原图与文件路径保留在内部记录中。文字摘要允许显示既有 120 字符预览，并非自动识别或删除敏感内容。

格式规范化从 Windows observer 中分离为纯逻辑。一次快照中有非空文件列表时选文件，否则有图片时选图片，否则选文本；无已知格式时不生成记录。空文本保留，空文件列表可以回退到图片或文本。规范化只选择格式；图像尺寸和缓冲区的有效性由既有图像准备逻辑检查，不能把无效图片悄悄改成另一种已采集内容。

文字预览继续折叠空白并最多保留 120 个 Unicode scalar；原文本和文字指纹不做该变换。图片继续使用原 RGBA 的内容指纹、PNG 编码和既有缩略图尺寸/字节限制。此阶段不读取系统剪贴板，不采集磁盘上的用户图片，也不改变持久化格式。

## 文件指纹的平台语义

Windows 保持既有指纹算法和字节输出：统一斜杠为反斜杠、去掉既有扩展路径前缀、转大写，并保持路径列表的顺序。这是已持久化历史的兼容要求，不在本轮重定义 Windows 文件身份。

macOS 保留每条路径的原始 OS 字节，不转大写、不替换反斜杠、不做 Unicode 归一化、不跟随链接、不调用 canonicalize。使用明确的格式域与长度边界编码路径列表，避免不同列表或非 UTF-8 路径经有损转换后得到同一指纹。相同路径序列必须稳定；大小写不同、反斜杠与目录分隔符不同、组合与分解 Unicode、顺序不同均保守视为不同记录。默认大小写不敏感卷上的同一文件可能出现不同拼写的重复记录，优先避免误合并；指纹不代表打开文件的授权或对象身份。

## 编译与运行边界

Mac 编译共享模型、格式规范化与预览模块；Windows observer、service、store 和粘贴实现继续使用原平台装配。不会为通过编译伪造 HWND、剪贴板序号或持久化成功。Mac 启动、设置与退出阶段均不创建历史服务，不轮询系统剪贴板，也不注册新的 IPC。宿主能力和 SDK 的当前支持矩阵不变。

现有 Windows 集成测试保留；新增共享核心测试在两端编译，Mac 路径语义测试只在 Mac 运行。旧 Windows 指纹使用固定向量单独验证，不能仅以“同一函数调用两遍相等”替代兼容性断言。

## 验收与后续边界

本单元自动检查：摘要 JSON 形状、文本边界、格式优先级与空输入、图像非法尺寸/缓冲区、PNG/缩略图输出、Windows 固定指纹和 Mac 路径区分。只使用内存合成内容。全仓验证、Mac 普通编译和 Find 预览编译应继续通过；本机通过不等于 Windows 原生回归完成。

后续仍需独立实现和审核：原生剪贴板 reader/observer、平台序号与停止后迟到回调、插件隔离的私有持久化、复制及外部写入竞争、授权撤回和退出生命周期。接入前应补齐各自的系统 API 与失败合同。使用测试内容的真实采集、跨应用复制和重启验证延后；粘贴与输入控制归 Task 10.2。Task 9 只能消费已通过对应验收的能力。
