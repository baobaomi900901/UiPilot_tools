# 插件分享中心与 Panel 文本交接协议

状态：独立设计审查通过，待用户审阅后进入实现计划。用户授权完善协议并反复审查；未授权本轮实施代码。拟议 Host 0.22.0、API/schema v1、分享合同 v1；以下新接口尚未实现。

## 1. 目标与范围

OCR 提取文字后，用户可编辑，按 Ctrl+K → 分享… → 翻译 → Enter；主界面切换至翻译 Panel，正文填入左侧原文区，由翻译插件立即开始翻译。是否自动处理由接收插件决定，宿主不把“接收数据”解释为统一的业务命令。

采用来源提供内容、目标声明接收入口、宿主匹配和交接的方案。不采用插件互相引用 ID 的直接调用，也不在首版引入工作流引擎。

首版为 Windows、单命令 submit Panel → Panel、text/plain、一次显式用户操作选一个目标。来源和目标可以是任何符合新合同的公开插件，不写死 OCR/翻译 ID。翻译结果也可注册为分享来源，支持用户逐次选择形成 OCR → 翻译 → 笔记链路。首版不支持同一插件向自身分享；这项限制只影响候选目标，不禁止之后从其他插件再次分享回来。

不包含 Window/mainResult 适配、图片/文件、后台调用、自动连锁、跨插件共享存储、返回历史栈和永久分享历史。接收入口可有多个并指向同一个 Panel，不借此开放目前不支持的多命令 Panel。

## 2. 当前基础与必要宿主改动

- Ctrl+K 的 onActions 目前只注册当前 Panel 文档中的回调；不能据此直接获得其他插件或系统的权限。
- PluginPanelController 当前只有一个 LiveSession；plugin_panel::mount 先 teardown 再创建目标。普通 open_plugin_panel 不能用于本协议的无损准备。
- 翻译模型目前将初始化文字排入任务，Ready 后开始翻译。分享准备阶段不能把正文塞进普通 invocation.input 或 update.data，否则可能提前执行。
- OCR 正文上限为 16384 UTF-8 字节，翻译输入为 8192 字节，必须检查接收方限制。
- 所有新增 IPC 接收真实调用 Webview 并核对其精确身份。不得用 WebviewWindow 参数绑定或仅校验父窗口 main；一个 OS 窗口包含多个 Webview。

新建独立的 ShareCoordinator 负责候选声明、分享票据、快照、交接状态和超时。Panel 控制器扩展为一个活动会话和至多一个待切换会话，复用既有会话、Runtime、Ready、权限与生命周期设施。分享控制器不接管 OCR/翻译业务；普通 Panel 打开路径保持原行为。

## 3. 声明与身份

拟议 Manifest 顶层字段为 share，形状如下（其余 Manifest 字段省略）：

```json
{
  "share": {
    "version": 1,
    "source": true,
    "receivers": [
      {
        "id": "translate-text",
        "title": "翻译文本",
        "commandId": "default",
        "types": ["text/plain"],
        "maxBytes": 8192
      }
    ]
  }
}
```

- source 与 receivers 均可省略；存在 share 时 version 必须为 1，且至少声明来源或一个接收入口。source 若出现必须为 true；receivers 若出现含 1–8 项。未知字段、null、重复 ID 拒绝。
- 首版只允许 Windows、旧式单 command、submit + panel + ui.panel，minimumHostVersion >= 0.22.0。接收入口 commandId 固定映射该旧式命令的内部稳定身份 default；不改变旧式 onCommand 中省略 commandId 的合同。以后扩展多命令时继续使用同一接收入口身份模型。
- 接收入口 ID 为插件内唯一 ASCII `[a-z][a-z0-9.-]{0,63}`，排除 __proto__/prototype/constructor；title 1–80 Unicode 标量且无控制字符；types 首版精确为 ["text/plain"]；maxBytes 为 1–16384 的整数。
- 目标键是 pluginId + receiverId；commandId 为经过校验的路由绑定。用户改启动词、插件显示名或入口标题不改变路由。插件更新后声明/安装代次变化使旧选择失效，即使 ID 相同也不重定向。
- share 是显式数据交换能力声明，不授予网络、剪贴板、文件或存储写入权限。用户在宿主列表中选择目标授权本次交换，不增加每次重复确认弹窗。旧包不声明则行为完全不变。
- 发现阶段只读已安装、验证过的 Manifest/索引，不执行候选插件，不广播正文。禁用、未安装、不兼容、非 Panel 与来源插件自身不进入候选列表；长度不适配的合法目标保留为禁用项并展示原因。

## 4. 数据合同与来源发布

首版载荷是精确字段的只读对象 `{type:"text/plain", text:string}`。text 必须是良构 Unicode、非空且非全空白，不含 NUL；保留原始空格、换行和文字，不 trim、截断、拼接命令或解释 HTML。正文最多 16384 UTF-8 字节；每个完整紧凑 JSON IPC/事件最多 65536 UTF-8 字节，两个上限都检查。源桥与宿主独立验证。

拟议可选 panel.share 来源接口：

- `onSource(provider): unsubscribe` 注册一个同步提供器，返回 `{revision: U64Decimal, payload}` 或 null。提供器在宿主索取时同步读取当前编辑全文，不发网络、不触发业务；正文不在平时上传。
- `invalidateSource(revision: U64Decimal): Promise<void>` 报告分享相关内容修订变化，不携带正文。源桥先同步使本地旧快照/回调失效，再发送会话绑定的通知；调用结果只表示宿主已接受失效，不产生分享。
- provider 返回的 revision 与最近发布修订一致；同一会话从 1 开始严格递增，不循环复用。编辑正文、换图、清图、加载/失败使可分享状态变化均递增；主题、布局、焦点不递增。首次注册必须先发布初始修订。取消订阅使待交接快照失效。
- OCR 仅在成功且当前编辑全文合法时提供载荷。分享与复制读取同一份编辑状态；不得使用上一次识别的旧原文。翻译可将当前有效译文注册为来源。

宿主生成“分享…”操作；插件不得自行调用 openShare/send(target) 绕过用户选择。提供器注册不产生动作票据。打开操作菜单时来源桥可在本地调用 provider 判断可分享性，只返回可用性/固定禁用原因，不上传正文；点击分享时重新取值。真实 Ctrl+K/菜单交互取得一次性来源菜单票据，点击分享后宿主索取快照；桥复核实际文档、会话、修订和票据。主输入触发菜单时，也必须向当前内容 Webview 的来源提供器取值。

快照固定后不替换其正文。宿主记录来源插件安装代次、会话/文档身份、revision、快照摘要和票据。摘要只用于匹配，不记录正文日志。目标列表只读取类型/字节数与声明，正文不进入普通搜索 input、历史或日志。

并发失效以宿主接受事件的顺序为准：提交检查之前已接纳的 invalidateSource 必须取消；已经完成逻辑提交后到达的失效不能追溯撤回目标。此规则不承诺异步 IPC 在用户本地编辑瞬间就完成跨进程撤销。提交前另执行一次来源确认握手，源桥重新调用 provider，核对 revision 和载荷摘要；不一致或不可分享立即取消，而不是发送更新后的文字。确认返回后至逻辑提交之间仍按宿主事件顺序仲裁。

## 5. 目标接收接口

拟议可选 `panel.share.onReceive(handler): unsubscribe`，接收函数必须在首次 onUpdate 注册前安装。事件精确字段为 `{version:1, transferId, receiverId, sessionEpoch, payload}`，宿主填入身份；不向目标泄露来源的图片、私有存储、凭据或任意元数据。transferId 为宿主生成的不可预测单次 ID，不接受插件自报的 ID 作为权限依据。

handler 是同步接纳函数：校验 receiverId，将正文写入其内存模型/编辑区，返回 `{accepted:true}` 或 `{accepted:false}`。不得在回调中等待翻译、网络、Runtime action 或长期保存。同步抛错、Promise 返回或非法返回值视为接纳失败；不能据此断言没有业务副作用。

宿主桥在调用 handler 前将该 transferId 标为已投递，在返回后自动报告接纳 ACK；同一文档重复事件不再调用 handler。业务工作由插件在本地同步接纳后延后执行，不必等待宿主收到 ACK，沿用当前活动会话和 Runtime 的正常授权。翻译必须在接纳后安排一次翻译；失败显示原文与重试状态。笔记类入口可只建立草稿，不自动保存。

Ready 是面板可用条件，接纳 ACK 是文字进入目标的确认，业务成功是第三个独立状态。宿主不把分享 ACK 当作翻译结果，也不代理业务重试。

## 6. 状态与两阶段交接

每个主窗口最多一个分享事务，全宿主仍只有一个活动 launcher Panel。状态为 `Choosing → Preparing → Committed → Accepted | DeliveryFailed | DeliveryUnknown`，未提交阶段还可结束为 `Cancelled | PrepareFailed`。Accepted、DeliveryFailed、Cancelled、PrepareFailed 是业务终态；DeliveryUnknown 是有限等待晚到 ACK 的不确定状态。提交后的主动结束、生命周期取消或恢复记录释放最终进入 Closed；Closed 的含义是关闭交付意图，不是业务回滚。每次状态转换核对同一个 transferId 和所有者；终态不因迟到 ACK 重新进入接纳流程，终态后的资源清理可进入 Closed。

### 6.1 Choosing：获取快照与选择

点击“分享…”后先在最多 2 秒内取得快照，再显示可搜索目标列表。首次索取超时或 provider/消息失败时废弃本次来源菜单票据，不创建目标，不接受迟到快照，反馈“来源内容暂不可用”，不自动重试；等待期间取消也废弃票据。用户 Enter 选目标即消费选中票据，连按/长按不重复准备。Esc 返回操作列表，Ctrl+K 关闭菜单，二者取消当前快照并恢复来源焦点/选区；重新进入分享重新取快照。

原菜单 provider 返回 null（例如插件模态打开）、来源不可分享或会话不活动时，不打开分享流程。无有效文字时显示禁用原因；没有匹配目标时显示“没有可接收此内容的插件”。无默认目标、不因只剩一个目标而自动执行。

### 6.2 Preparing：保留来源，准备无正文目标

1. 重新验证目标声明、安装代次、启用状态、ui.panel 授权和来源快照。正文需同时满足宿主及目标 maxBytes；超限拒绝，保留来源。
2. 创建独立且唯一的待切换 Panel 会话/文档，标签、nonce、epoch 与活动来源不同。内容 Webview 隐藏、不接收输入、不抢焦点，不占用活动 Panel 路由。来源及其图片/编辑状态保持原对象，不依赖重新运行 OCR 来恢复。
3. 目标 Runtime 通过既有 onCommand 执行无正文初始化：input 为 ""，没有 image；新增 context.entry 为 `{kind:"sharePrepare", receiverId}`。Runtime 请求绑定到待切换会话与受限准备权限，正常请求的 context.entry 为缺省。目标不能把该阶段当作正式接收。
4. 只允许准备阶段必要的插件自身 storage.get、settings.get/isSecretConfigured，以及宿主握手/布局/主题注入。宿主拒绝 storage.set/remove、网络/业务服务、剪贴板、语音、计时器、通知、文件选择、外部打开、普通 Runtime actions 和抢焦点/隐藏主窗口等能力；private IPC 同样逐次检查待切换状态，不能只靠 JS 隐藏 facade。已获安装授权也不能跳过准备限制。
5. Runtime 成功返回初始化 data，目标执行 onUpdate（新增 `entry:{kind:"sharePrepare",receiverId}`），注册有效 onReceive 并完成现有内容加载/更新 ACK。宿主记录 Prepared，但此时**不投递普通 onReady**，不提供来源正文。只声明而未注册接收器按准备失败处理。
6. 普通 Panel 的 mount/teardown、bounds/show、ready 和 focus 路径必须区分活动/待切换，准备路径不能沿用先销毁来源的行为。目标准备中来源只受宿主模态遮罩保护而不被销毁；来源异步内容变化照常报告失效。

Preparing 失败/取消只销毁目标待切换文档并撤销其权限，来源有效时恢复其焦点和编辑状态。不自动重新准备。目标 Runtime 若仍物理执行，撤销其逻辑权限但保留原物理占用直到完成/原期限，不因取消就启动第二个 handler。

### 6.3 提交点：原生切换准备与逻辑提交

目标 Prepared 后，先执行来源确认握手，再在主线程安排可撤销的 UI 切换准备：校验目标原生 Webview 存活并设定 bounds，暂时禁用主输入，隐藏来源内容并显示宿主交付占位层，准备 tag 与主输入焦点；目标内容仍隐藏。使用内部焦点切换票据避免正常 blur 将两个会话销毁；来源暂时不可见不等于逻辑 host_hidden。此时不发送正文、不提升目标副作用权限；来源暂不销毁。原生准备失败时关闭占位层并恢复仍有效的来源。

原生切换完成后，在宿主协调器一个短临界区内重新核对来源确认、快照、双方安装/会话/授权代次、主窗口可见性、导航意图及未取消状态。临界区不调用插件、Webview.eval、网络或等待 ACK；所有参与的生命周期变更必须经过同一提交门或提供不可被并发失效穿透的版本守卫。

通过该检查后，唯一逻辑提交点同时：将票据标为 consumed、把目标设为唯一活动 Panel、撤销来源的业务权限并把事务标为 Committed。从此不回滚到 OCR、不接受来源晚到消息、不自动重发。原生窗口操作不是数据库事务；“原子”只描述上述授权/路由状态，不能承诺 OS 显示调用绝不失败。

提交后清理来源，但保留宿主交付占位层和主输入禁用状态；目标内容 Webview 仍隐藏，逻辑上获得普通活动会话资格，可以运行初始化回调及接纳后的业务。此时不允许用户编辑目标或向其主输入提交，不能只用主页面 CSS 遮罩假定能拦截原生子 Webview 输入。目标获得一次正常 Ready，再收到一次不含正文的内部分享通知（transferId、receiverId、目标初始化身份）。仅有两个事件的发送顺序不够：目标接收桥必须建立“当前初始化对应的 Ready 回调已同步执行完成”屏障。通知提前到达时只暂存一份，不能提前接收正文；当前会话/初始化不匹配则丢弃。

屏障通过后，由宿主注入桥调用一次私有 claim_share_delivery，宿主在提交门内核对精确目标文档/会话/安装代次、活动资格、transferId、交付意图未撤销、尚未发放以及提交后 2 秒的单调时钟期限，通过才标记 deliverySpent 并返回完整接收事件。这是内部交付握手，不向插件开放查询或反复拉取正文的 API。桥在响应回来时还必须检查本地同一 transferId 的交付意图仍为 pending；先将其改为 consumed，再至多调用一次 onReceive。已 revoked/consumed 的响应直接丢弃，不能仅检查文档/sessionEpoch。初次调用的响应丢失不重试；重复 claim 不返回正文。这样迟到通知/Ready 不能靠 Webview 本地计时重新领取过期正文。

2 秒限制宿主首次发放资格及正常 ACK 等待；已经在期限内发放、响应或 handler 仍在途时，只有交付意图未撤销的当前目标才可完成一次，可能先显示 Unknown、再收到晚到接纳 ACK。不得把此场景误称为“截止时刻后绝不会执行”。若目标会话或交付意图已失效，桥必须丢弃晚到响应，不调用 handler。屏障失败/退出时废弃暂存通知。

分享准备入口要求必要模型/偏好初始化全部在 Prepared 前的 onUpdate 及其 ACK 中完成。该入口首次正式 onReady 仅作同步激活通知，不能承担异步模型初始化；返回 Promise、抛错或非法返回被视为分享 Ready 合同错误，桥不调用 onReceive，并报告 DeliveryFailed。不等待该 Promise，也不允许插件在异步续体中重置模型；若插件违反合同已产生副作用，宿主不声称能够回滚。普通非分享入口允许异步 onReady 的既有合同不变。全部 Ready 通知回调须在初始化前注册；没有回调时屏障为已完成。

正文只通过分享事件发送，不能同时放入 onCommand、onUpdate.input 或 data 造成双重执行。目标顶部仅显示命令 tag，宿主输入为空，正文进入目标多行编辑区。Accepted 后才显示目标内容、启用主输入并恢复默认主输入焦点；之后用户可进入编辑区。该次翻译必须由 onReceive 接纳触发；后续主题/布局更新只更新 UI，不再次安装无正文初始化模型、不清空已收到正文。用户后续主动输入/编辑沿用插件既有规则，包括以自身内容修订阻止旧业务响应覆盖新输入。接纳后原生显示失败只反馈宿主错误，不回滚或重新交付；这不扩大接纳后正文恢复承诺。

### 6.4 Accepted、失败和不确定结果

| 情况 | 状态和行为 |
| --- | --- |
| 提交前目标初始化、能力检查、来源确认或原生切换失败 | PrepareFailed；目标清理，来源仍有效则保留并恢复；不重试 |
| 提交前来源被用户关闭/隐藏、插件禁用或卸载 | Cancelled；两边都清理，不试图复活已失效来源 |
| 提交后收到匹配的 accepted ACK | Accepted；分享结束，目标自主处理正文 |
| 提交后 handler 拒绝/抛错/格式无效 | DeliveryFailed；留在目标，显示未完成接纳，不自动重发/回滚 |
| 提交后 eval/通信/ACK 超时等无法判明是否接收 | DeliveryUnknown；留在目标或宿主恢复视图，提示“接收状态未确认”，不宣称翻译失败或未执行 |
| 提交后、Accepted 前目标文档意外丢失 | DeliveryUnknown；撤销该文档后续 ACK 资格，保留有界正文恢复副本，不重建/重投 |
| Accepted 后目标文档丢失 | 按目标正常生命周期清理；宿主已释放正文，不承诺恢复 |
| 已接纳，但翻译网络/权限/额度等失败 | 分享仍为 Accepted；目标保留原文并提供自己的重试 |

只有 Committed 后、Accepted 前的 DeliveryFailed/DeliveryUnknown 保留宿主临时正文恢复资格。此时目标文档意外丢失或无法显示正文，宿主提供当前事务的临时只读正文恢复视图，允许用户显式复制及关闭；不提供自动重投按钮，不重新运行来源。该复制属于宿主明确用户动作，不借用目标插件权限。接收状态不确定时同样可查看正文；用户另行开启流程是新操作，不把其误称为安全自动重试。Accepted 后宿主立即释放副本，之后崩溃不承诺宿主恢复。

非预期文档丢失与用户撤销不同：前者在接纳确认前转 Unknown 并保留有界恢复副本，但撤销丢失文档的 ACK 资格；用户主动导航/隐藏/退出、目标禁用/更新/卸载/撤权等则立即释放正文与恢复资格，不以“崩溃恢复”复活失效身份。并发时任何主动撤销已经被宿主接纳，就优先执行释放。

仅保证一个活着的宿主进程内，同一 transferId 至多一次通过 claim 响应发出正文、目标桥至多一次调用 handler。返回正文前先记录 deliverySpent；响应传输失败也不解除。ACK 幂等，必须对应已发放正文的记录，并绑定目标安装代次、精确文档、sessionEpoch、transferId；迟到 ACK 不能复活已结束/替换会话。不能承诺外部服务 exactly-once、进程崩溃后的交付成功或回滚。

### 6.5 未接纳交付的输入所有权与结束握手

每个目标文档只允许一次打开时的分享，桥私有维护该 transferId 的 `pending → consumed | revoked` 状态，不可从 consumed/revoked 恢复 pending。这与宿主 deliverySpent 不同：宿主可能已发出正文，但桥仍等待响应。源会话和目标文档依然存活，不代表交付意图依然有效。

Committed 到 Accepted 期间不开放主输入或目标编辑，Unknown/DeliveryFailed 时由宿主占位层展示状态、临时正文和“继续编辑目标”“关闭”等操作，不直接解除输入限制。仍有效的晚到 ACK 可按规则完成 Accepted；用户选择继续编辑则走以下结束握手：

1. 宿主先在提交门撤销该 transferId 的进一步 claim/ACK 资格，终止该接收事务；保留必要的无正文去重记录。
2. 通知精确目标文档的桥撤销 pending 交付意图，桥同步标记 revoked、丢弃暂存通知和之后的 claim 响应，再回报撤销 ACK。已 consumed 的调用只返回已消费/已撤销确认，不能重新接收。
3. 宿主只有收到当前文档对应的撤销 ACK 后，才允许显示目标内容、启用编辑/主输入提交或在此文档开始新的分享。确认前用户输入不得落入目标。撤销确认最多 2 秒；无法确认则销毁这个目标文档，不把未确认的文档开放给用户，保留仍有资格且未到期的宿主正文恢复视图。

关闭恢复视图、新分享、新输入/导航意图、恢复期限到达等结束操作也必须应用这条规则，不能只释放宿主记录而让桥 pending 继续存在。若动作本身会销毁目标文档（隐藏、退出、切换其他插件、撤权等），可直接销毁代替等待撤销 ACK；在销毁确认或撤销 ACK 前不把这个旧文档重新开放给输入。正文隐私释放立即执行，不等待撤销 ACK；无法安全保留文档时退回宿主视图。

新分享开始前先结束旧事务并释放旧恢复副本；若要以同一目标文档作为新来源，先取得上述本地撤销确认。首次交付已经 Accepted 时 handler 已消费，不再需要等待撤销确认来编辑/分享。

该握手只阻止**尚未开始的** onReceive。若 handler 在撤销之前已开始，它及已经发出的外部业务不能承诺回滚；用户编辑后的异步结果覆盖仍由目标已有的内容修订规则防护。用户得到编辑权之后，任何旧 pending claim 响应都不得再启动 handler。

## 7. 超时、释放与并发失效

- 首次索取来源快照从点击分享起最多 2 秒；Choosing 从快照建立起最多 120 秒；Preparing 从目标确认起最多 30 秒，内部 Ready/更新/来源确认单步最多 2 秒且不能延长总期限。原 Runtime 的物理 30 秒期限不因取消/重试重置；目标 Busy 时返回明确不可用，不排队。
- 提交后的 Ready 同步完成屏障、首次正文 claim 发放及正常接纳 ACK 等待共用最多 2 秒期限；超时进入 DeliveryUnknown，不再次发送通知、不再次 claim 正文。稍晚且仍属于当前存活目标文档/事务、交付意图未撤销的接纳 ACK 可以将 Unknown 更正为 Accepted，但绝不再次调用 handler；目标已退出、意外丢失、ACK 资格撤销或恢复记录已释放则忽略。未在期限内领取的正文不能被迟到 Ready/通知重新领取，已发放在途响应遵守 6.3/6.5 的完成与撤销规则。
- 主窗口隐藏、退出、来源/目标更新/禁用/卸载、权限/设置代次变化，以及新的导航意图在提交前取消事务。提交后按目标的正常生命周期撤权/清理；重新授权不恢复旧事务。取消与提交竞争由共同提交门决定：先取消就不能提交，先提交就不能退回来源。
- 主题/布局更新不重置分享、不改变正文修订、不重复准备或投递；更新只改变同一待切换/活动目标的 UI。目标首次 Prepared 必须对应最新已 ACK 初始化；普通主题变化不重发来源正文。
- 提交前快照在取消/失败/过期时立即释放。Accepted 后释放宿主持有的正文，仅目标自身内存模型保留；DeliveryFailed/DeliveryUnknown 的恢复副本从进入该状态起最多保留 120 秒。关闭恢复视图、开始新分享、主动导航、主窗口隐藏/退出或目标安装/授权身份失效时立即提前释放，并撤销接收资格或销毁文档，不能只清理正文。继续编辑与明确关闭不同：本地撤销确认成功后释放副本；确认失败并销毁目标文档时保留原有界副本供宿主展示，但不能延长原期限。接纳前非预期目标文档丢失不触发提前释放，只撤销该文档 ACK 资格并继续原恢复期限，重复故障不能延长期限。宿主关闭后不恢复正文。目标清理按既有插件生命周期，不要求不可信插件忘记已收到的数据。
- 去重元数据不含正文，Committed 记录保留到对应目标会话结束；每个目标会话只接收其打开时的一次分享。清理后旧 epoch/文档仍不可匹配，不为重启恢复去重表而落盘。
- 来源 invalidate/取消与目标 ACK/Ready 分别绑定各自身份；来源正常销毁是提交后的预期行为，不会误取消已经提交的目标事务。全局仅一个未完成分享；新显式分享先取消旧的未提交事务，已提交的旧事务不重放。

## 8. 界面和权限边界

宿主统一渲染 Ctrl+K 菜单和目标选择层，使用既有 Light/Dark token、键盘和可访问规则。来源插件不自己画目标选择器。显示接收入口标题及插件名称；同名插件仍以稳定 ID 区分。固定名称排序，以 pluginId/receiverId 破同序，不增加默认厂商优先、推荐算法或持久最近使用。

Choosing/Preparing 层拦截 Enter、Esc、Ctrl+K 和 Tab，背后内容不同时接收按键。IME composing 不确认目标，Enter 长按只消费一次票据。Preparing 显示目标和进度，可取消；Committed 后先显示宿主交付占位层，Accepted 或安全结束握手完成后才按目标面板正常交互。Unknown/Failed 层的按键属于宿主恢复操作，不能透传成目标提交。

来源只能提供自己的内容，不能读取其他插件数据；接收者只能读取用户本次选给自己的正文。宿主内部 selector 票据与来源菜单票据不同，插件不能伪造目标选择、枚举已安装插件详情、编程唤起分享或进行后台自动链路。UI 文案仅显示安全固定错误及目标名称/限制，不拼原始异常、正文或凭据。

业务效果仍要求目标自己的网络、服务、存储、剪贴板等授权。未配置有道不阻止“接收文本”本身；翻译接纳后可显示配置错误并保留原文。分享不是业务权限预授权，也不自动更改安装授权或导入历史。

## 9. 模块与兼容交付

Host 交付单元：Manifest/CLI/SDK 的版本门；share 索引和选择层；source 快照桥；ShareCoordinator；Panel 待切换会话与受限初始化；提交门、生命周期/焦点协调；目标接收桥和临时恢复视图。这些组成同一个可验收能力，不能只交付菜单而省略失效/恢复。

插件交付单元：OCR 注册来源、维护正文修订；翻译声明接收入口、准备阶段无正文无业务、正式接纳写原文并触发一次翻译，同时注册译文来源。插件业务和 UI 保留在包内。Manifest、SDK 类型/Schema、Rust/CLI 校验及测试同步更新；该能力拟以 Host 0.22.0 为门槛，旧插件和普通打开/输入合同保持不变。

本轮只交付设计及审查记录，不修改上述实现、插件版本或用户安装状态。实现计划需要用户另行确认设计后开展。

## 10. 验收矩阵

1. OCR 编辑后全文分享至翻译：Ctrl+K 可发现多个不同 ID 的文本接收者，选择哪个只交给哪个；翻译 tag、左侧原文、一次自动翻译一致；剪贴板原值不被分享改写。
2. 来源空/加载/错误不可分享；中文、多行、前后空格完整；NUL/坏 Unicode/超限封包拒绝；16384 字节来源不能截断后交给 8192 字节目标，恰好边界合法。
3. 真实生成的 Tauri IPC 在 main 与 Panel 子 Webview 共存时工作；来源/目标/准备页不能冒用 main、其他文档、旧 epoch、票据或接收入口。
4. 候选列表无正文广播、无插件执行；同名/改名/多个入口不会错投，旧命令 ID 缺省语义不变，同插件目标被排除。
5. 准备阶段初始化和准备页直接 private IPC 尝试网络/服务/写存储/剪贴板/焦点等均失败；自身只读设置/存储正常；source handler 与 source OCR 状态不被目标准备破坏。
6. 首次快照索取无响应/同步 provider 阻塞/迟到回复：最多 2 秒结束，不创建目标、不接受已取消票据。目标加载失败、无 receiver、初始化抛错、Busy、超时、用户取消：来源 DOM、图片与编辑文字仍是原对象；模态关闭后焦点/选区恢复；已撤权/关闭的来源不复活。
7. 固定快照后正文变化→invalidate 被宿主接纳→确认目标，必须取消；source 确认读取新修订也取消；不把新文字悄悄替换旧快照。确认后 invalidate 与 commit 两种顺序分别覆盖，已提交不追溯撤销。
8. 更新目标插件、撤权、隐藏、新导航分别发生于准备、原生切换、提交临界区、投递和 ACK 时：按提交门先后只有一个有效结局，不能复活权限或误恢复来源。
9. 目标准备无正文、不发普通 Ready；Ready 注册/更新 ACK/Prepared/提交/Ready 同步回调完成/claim/receive/接纳 ACK/业务请求顺序在实际宿主调度与生产桥中验证，不只测试孤立模型。内部通知先到不能先领取正文；分享 Ready 返回 Promise/抛错不调用接收器；迟到 Ready 不取得过期正文；普通异步 Ready 不回归。
10. 连按、重复通知/claim/ACK、通知 eval 已执行但回报失败、claim 响应丢失、ACK 丢失、延迟回报：正文最多发放一次、handler 至多一次，外部业务不由宿主自动重试；期限内已领取但响应迟到可在同一有效目标完成一次并更新 Unknown→Accepted；期限后首次 claim 必须拒绝；退出后的响应/ACK 无效。
11. 提交前原生切换准备失败不交付正文；恢复来源失败不冒充成功，关闭不安全目标并显示宿主错误。Accepted 后原生显示失败按 6.3 反馈，不回滚或重新交付。提交后、Accepted 前文档意外崩溃有有界正文恢复且旧 ACK 无效；Accepted 后崩溃不恢复宿主已释放正文；主动导航/隐藏/撤权与崩溃竞争时按隐私规则提前释放。均不复活 OCR、不重投。
12. 主题切换不取消分享、不重做业务；普通 `/translate`、划词、OCR 两种入口、主输入和内容焦点、旧插件 Ctrl+K 不回归。
13. 临时正文在取消、完成、超时、隐藏、身份失效、新分享时按规则清理；日志/磁盘/剪贴板历史无分享正文副本。普通业务插件是否主动持久化由自己的用途和授权约束，分享不保证已接收数据可撤回。
14. 可用假接收插件展示接纳后只建草稿，证明宿主未写死自动翻译；翻译→另一个文本入口需再次用户选择，收到数据不会自行打开分享。
15. claim 已发放但响应延迟→Unknown→用户继续编辑→本地撤销 ACK→新编辑/主输入提交→旧响应到达：新正文保留，旧 handler 不执行。关闭恢复层、开始新分享、恢复到期分别重复该顺序，必须撤销本地资格或销毁旧文档。撤销 ACK 丢失时不得开放旧文档输入；已消费 handler 的业务不能被错误宣称回滚。

自动化使用假服务、假剪贴板和模拟 Runtime/Webview；原生窗口、焦点、双主题与真实供应商由用户手动验收，不使用 Computer Use。以上是待实现验收要求，不是已通过的测试报告。
