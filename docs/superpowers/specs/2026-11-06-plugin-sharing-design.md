# 插件文本分享：单面板首版

状态：2026-11-06 用户明确确认，选择翻译后异常就在翻译侧报错，不返回 OCR。本修订替代此前的双面板无损交接设计及其生命周期子计划；原始设计可从 Git 历史恢复。实施授权延续，不再为已确认的范围重复询问。

## 目标

OCR 当前编辑文字 → Ctrl+K → 分享 → 用户选择翻译 → 翻译标签与文本编辑区 → 翻译插件立即翻译。宿主通过声明发现所有兼容接收者，不写死 OCR/翻译 ID。是否立即处理由接收插件决定，另一个接收插件可以只保留草稿。翻译结果也能作为来源。

## 边界与失败行为

- 仅 Windows、现有单命令 submit Panel、text/plain、一次明确选择一个目标；Host0.22.0、API/schema1。
- 选目标前取消只关闭选择器；选目标后按现有普通打开流程离开来源。宿主只有一个活动 Panel，不创建第二个待切换 Panel，不保存来源 DOM/图片以供回滚。
- 翻译业务失败由翻译面板显示，保留已接收原文并允许插件自身重试，分享不代替业务重试。
- 目标加载/初始化/接收失败时留在目标标签下显示明确错误；目标界面不能加载时用宿主错误区。不得返回 OCR、自动重发或自动重启目标。错误区可保留本次原文供显式复制；离开目标或关闭后释放。
- 未确认交付时禁止目标编辑；失败或取消直接结束该目标投递会话，后续用户重试使用新会话。首版不提供旧未知会话的继续编辑、撤销 ACK、回滚、恢复历史或自动重试协议。
- 不实现全局权限守卫、管理器锁重构、受限 sharePrepare Runtime、双面板原子提交、通用原生显示队列。复用现有安装授权、会话失效和普通 Panel 生命周期。

## 声明与公共接口

保留已实现的 manifest `share: {version:1, source?:true, receivers?:[...]}` 及其校验：receiver id/title/commandId/types/maxBytes，最多8个入口，仅text/plain，每个上限1–16384UTF-8字节；source或receivers至少一个。仅声明并获ui.panel的兼容Panel。旧命令commandId缺省语义不变。

`panel.share` 可选，首版只包含：
- `onSource(provider)`：同步提供 `{type:"text/plain", text:string}` 或null，返回unsubscribe。分享操作取当前内容快照；不引入revision/invalidateSource/提交前再确认协议。
- `onReceive(handler)`：注册同步接收器，返回unsubscribe。事件 `{version:1, transferId, receiverId, sessionEpoch, payload}`，handler返回严格 `{accepted:boolean}`；异步业务由插件自行启动。Promise/throw/非法返回作为接收错误。

文本不trim、不截断，保留原始空格/换行；拒绝空白、NUL、不合法Unicode、超过宿主或目标字节上限。包含所有字段的实际IPC封包上限65536字节。超过目标上限显示不可选择原因，不能静默截断。

未发布的原SDK复杂分享接口可随本修订简化；manifest/source/receiver能力及Host版本继续保留。没有公开枚举其他插件、直接发送或自动串联的API。

## 宿主流程

1. 在现有Ctrl+K操作菜单注入宿主分享动作。main输入焦点和内容焦点都复用现有菜单链路；来源无有效文字时禁用并说明原因。原插件菜单null/模态状态沿用现有规则。
2. 获取同步来源快照，最长2秒；主界面显示可搜索的兼容接收者，按稳定pluginId/receiverId选择。只读取声明，不执行候选插件。相同插件目标排除；无默认自动选中执行。来源文字变化不偷偷替换已取快照。
3. 选择器使用一个当前来源会话绑定的显示抑制标记，隐藏当前子Webview并防止bounds回调重显；取消时只恢复仍有效的当前来源。无需新通用显示队列。
4. 用户选择后通过现有普通Panel打开/空输入初始化。顶部切换为目标tag，宿主查询输入保持空；正文不进入launcher query/history，也不通过Runtime命令广播。
5. 目标完成普通onUpdate及Ready回调（沿用普通异步Ready语义）并注册接收器后，注入桥通过私有IPC领取一次正文。宿主先标记已领取再返回；桥先标记已调用再调用handler。初始化与领取绑定精确目标会话/文档/初始化身份。总启动交付期限30秒；不重试丢失响应。
6. 目标交付等待期间保持内容隐藏、主输入禁用；接纳后显示普通目标并开放输入。超时/接收失败结束这个目标投递会话，在目标tag下报错；不复用可能仍有迟到响应的文档供编辑。业务失败发生在已接纳后，由目标正常处理。
7. 主题/布局只更新UI，不重新初始化模型或再次接收正文。新导航、关闭、隐藏、卸载/撤权沿用现有会话失效并释放这次分享数据；任何迟到结果不得写入新会话。

仅需要一个短生命周期的分享记录：选择中→打开目标→交付中→结束/错误。可拆小模块，但不建设跨管理器事务框架。

## 调用与数据边界

私有IPC核对实际调用Webview，不能只检查父window。目标列表、选择和错误恢复仅main可访问；来源快照仅当前来源文档可提交；正文仅精确当前目标一次可领取。选择入口在宿主UI，插件不能自动选择目标。

Tauri emit_to可被Any订阅监听，因此正文、目录和私有票据不经过通用事件总线。使用精确Webview注入通知或无数据dirty信号加main认证拉取；正文经私有claim响应。无日志/磁盘/剪贴板历史副本，分享不自动改写剪贴板。

## 必须验证的完整链路

- OCR编辑后的多行文字到翻译，只执行一次翻译；目标普通业务失败保留原文、显示错误、不恢复OCR。
- 多目标明确选择；独立草稿接收者不自动调用业务；翻译结果可经新的用户选择继续分享。
- 空/加载/失败来源、大小边界、目标不兼容、重复Enter/通知/claim、迟到结果、新导航、初始化失败。
- 实际生成桥与真实Tauri命令绑定的调用方检查；错误源/目标/旧会话不能获取或发送本次正文。
- 候选发现无Runtime执行；正文不广播；普通OCR两种入口、再次粘图、普通翻译/划词、Ctrl+K及主题更新不回归。

自动化仅使用假服务、假剪贴板、mockRuntime和JSDOM。禁止Computer Use；原生焦点、双主题、真实供应商及剪贴板由用户手动验收。
