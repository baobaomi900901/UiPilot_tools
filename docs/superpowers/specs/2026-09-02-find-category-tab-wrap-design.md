# `/find` 类型焦点正向循环设计

## 目标

当键盘焦点位于 `/find` 左侧类型列表的最后一项“压缩包”时，再次按下不带修饰键的 `Tab`，焦点循环回第一项“全部”，避免焦点离开未固定的 `/find` 窗口并触发窗口隐藏。

## 范围

- 仅修改 `/find` 类型列表的正向 `Tab` 边界行为。
- 中间类型继续使用浏览器原生 Tab 顺序。
- 焦点循环不改变当前筛选类型；筛选仍由既有按钮激活行为控制。
- 不改变 `Shift+Tab`、方向键、搜索框、图钉、关闭按钮或窗口失焦隐藏规则。

## 实现设计

在类型按钮层处理键盘事件。仅当以下条件同时满足时拦截事件：

1. 当前按钮是 `FIND_CATEGORY_ORDER` 的最后一项。
2. 按键为 `Tab`。
3. 未按下 `Shift`、`Ctrl`、`Alt` 或 `Meta`。

处理时调用 `preventDefault()`，并把焦点移动到第一项“全部”。其他按键和其他类型按钮不做处理，继续沿用原生行为。实现使用类型按钮引用或当前导航容器内的首个类型按钮，不引入新的全局键盘路由。

## 状态与失败行为

该交互只移动 DOM 焦点，不写入 `FindCore` 状态，也不发起搜索、固定或隐藏请求。如果第一项按钮不可用或不存在，则不抛出异常；页面保持当前状态。

## 验证

在 `src/find-view.test.tsx` 增加回归测试：

- 聚焦“压缩包”，发送无修饰键 `Tab`。
- 断言事件被拦截，活动焦点变为“全部”。
- 断言当前筛选类型不因焦点移动而改变。

同时运行 `/find` 前端测试，并确认既有“只有类型按钮进入 Tab 顺序”的测试继续通过。
