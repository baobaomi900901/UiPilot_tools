# 剪贴板历史：按焦点查询与复制的宿主能力请求

状态：用户已明确授权同时修改主程序和插件；已实现于 Host 0.17.0 / 剪贴板历史 1.2.0。

## 用户需求

主输入框输入文字，Enter 查询文字记录和文件名；ArrowDown 将实际键盘焦点移入记录列表。记录项获得焦点后，ArrowUp / ArrowDown 切换记录，Enter 将完整记录写入系统剪贴板。Ctrl+K 按打开前焦点显示匹配的操作。

“设置到剪贴板”按仅复制理解：成功后保持当前界面和列表焦点，不自动粘贴到外部应用。成功、失败只写入宿主状态栏左侧；右侧保留“操作 Ctrl+K”。

## 已确认的问题和 API 缺口

- 插件 `package/plugin.json` 声明 `hostKeys` 包含 Enter，且 `hostKeyFocus: host`。`package/dist/panel.js` 将该 Enter 调用 `clipboardHistory.paste`，与输入框 Enter 查询冲突。
- 插件 `onUpdate` 未使用 `update.input`；当前列表只做分类过滤。内容区本地 keydown 只处理 Tab / Delete，没有完整的上下键和 Enter 逻辑。
- 公开 `clipboardHistory.list()` 没有查询参数。文本摘要最多 120 个字符；文件组只暴露 `firstFileName` 和数量。用这些摘要匹配会漏掉较长原文及同组其他文件名。
- 公开 `clipboardHistory.paste({ id, routeSequence })` 要求真实的宿主 Enter 路由票据；随后写剪贴板、隐藏主窗口并向外部窗口粘贴。不能用伪造路由票据或把该操作包装成“复制”。
- Panel 没有仅按历史记录 ID 恢复剪贴板的接口；拿摘要调用普通文本复制也不能保留全文、原图和文件列表。

合同依据：`docs/plugin-sdk/public-plugin-v1.md` 的 Panel、Host Keys、clipboard history 章节；`docs/plugin-sdk/uipilot-plugin-api-v1.d.ts` 的 `UiPilotPluginPanelClipboardHistoryApiV1`。

## 建议宿主能力

### 按全文和文件名查询

扩展 `clipboardHistory.list({ query?: string })`，无参数保持现有行为。查询在宿主持有的历史数据上执行，返回现有摘要结构，不向插件暴露完整原文、文件路径或原图。

- 去除查询首尾空白；非空查询按不区分大小写的连续子串匹配全文或文件组中任意一个文件名（含扩展名，不匹配父目录）。输入上限建议为 512 个 Unicode 字符，越界返回明确错误，不静默截断。
- 空查询显示全部记录；非空查询不命中没有可搜索文字的图片。分类过滤与查询条件取交集，保持宿主原有最近记录排序。
- `onChanged` 保持兼容。插件收到变更且存在查询时重新查询，使用会话、请求代数和 revision 防止旧查询覆盖新结果；不得把未过滤的推送快照直接放入查询列表。

### 仅复制历史记录

新增 `clipboardHistory.copy({ id })`，成功返回 `{ outcome: 'copied' }`，仅在实际系统剪贴板写入成功后完成。

- 新增 `clipboard.history.copy` 权限，依赖 `clipboard.history.read`；设置权限页、安装授权、Schema、CLI 和 SDK 同步支持。现有历史粘贴能力及授权保持兼容，不自动授予新增权限。新增复制权限需要用户在设置权限页明确开启；更新和重新加载保留之前的显式授权或撤销状态。
- 当前 Panel 会话内由用户显式操作触发，宿主校验插件身份、权限、会话和记录可用性。不得依赖外部粘贴目标或 Enter 的粘贴票据。
- 按 ID 写入完整文本、原始图片或文件列表；不切换窗口、不隐藏、不模拟 Ctrl+V、不自动重试。
- 失效会话、权限撤销、记录删除/不可用和剪贴板被占用应明确失败。旧回调不能覆盖新会话的状态提示，异步写入仍遵循宿主既有权限与会话校验边界。

## 插件接入与焦点交互

| 焦点 | 按键 | 行为 |
| --- | --- | --- |
| 主输入框 | Enter | 提交查询，保持输入框焦点；不复制或粘贴 |
| 主输入框 | ArrowDown | 有结果时进入选中记录，没有选中项时进入第一条；无结果时保持输入框焦点 |
| 记录项 | ArrowUp / ArrowDown | 在当前查询和分类结果内移动；首尾停止；选中、焦点与滚动同步 |
| 记录项 | Enter | 复制当前记录到系统剪贴板，保持界面与焦点 |
| 内容区 | Ctrl+F | 返回主输入框，保留查询文字 |
| 当前插件 | Tab / Shift+Tab | 保留下一/上一分类；列表焦点随结果调整，空列表安全退回输入框 |

实现时移除插件对输入框 Enter 的 Host Key 接管，利用默认 submit 和 `onUpdate.input` 查询。ArrowDown 使用现有 content 焦点路由；列表自行处理其本地方向键和 Enter。不得用“选中高亮”代替真正的键盘焦点。鼠标选择与键盘选择共用同一活动记录。

Ctrl+K：

- 输入框上下文：显示宿主提供的“搜索 / Enter”，不重复注册；可提供“进入记录列表 / ↓”。不显示记录复制或删除动作。
- 记录项上下文：提供“复制到剪贴板 / Enter”“上一条 / ↑”“下一条 / ↓”“删除当前记录 / Delete”，无可用对象时省略或说明禁用原因。
- 通用：下一分类 / Tab、上一分类 / Shift+Tab、返回搜索框 / Ctrl+F。复用宿主已有动作，避免重复。
- 菜单打开前冻结对象上下文，关闭时恢复焦点。记录、查询、分类或会话变化后旧动作失效；菜单自己的 Enter/方向键不再传给后方列表。
- IME 组合输入、文本编辑、长按 Enter、操作进行中不得造成重复查询或重复写剪贴板。

## 验收

1. 复制一段超过 120 字的测试文本，输入只位于末尾的关键词，Enter 能找到完整记录；输入期间不执行复制。
2. 复制多个文件，按第二个文件的文件名查询能找到整组记录；不同分类下正确取交集。
3. 输入框 Enter 始终查询；ArrowDown 将真实焦点移至记录；上下键移动和 Enter 复制互不串用。
4. 文本、图片、文件三类记录复制后手动粘贴，验证数据完整；复制时不触发外部应用粘贴或隐藏窗口。
5. Ctrl+K 在输入框、记录项、空结果和分类切换后的动作与焦点一致；没有重复“搜索/返回搜索框”。
6. 搜索期间历史更新、快速连续查询、记录删除、权限撤销和窗口关闭不会产生旧结果覆盖或误复制。
7. 单测覆盖查询匹配、焦点状态、菜单回调失效、权限与写入失败；真实 Host 验证跨 WebView 焦点以及真实剪贴板。仅在插件预览通过不能代替宿主验收。
