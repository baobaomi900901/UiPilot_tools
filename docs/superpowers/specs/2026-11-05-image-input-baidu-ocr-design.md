# 主输入框图片粘贴与百度 OCR

日期：2026-11-05

状态：用户于 2026-11-05 确认；进入实现。

## 用户确认的目标

1. 激活主程序，焦点位于主输入框。
2. Ctrl+V 粘贴一张图片。
3. 宿主识别图片输入，下方结果列表自动列出有 OCR 能力的插件。
4. 用户选择 OCR 插件并按 Enter，开始识别。
5. 主界面显示 OCR 文字结果。
6. 用户再次按 Enter，将识别全文复制到剪贴板。

第一版默认使用百度 OCR，并复用设置中用户已经配置的百度 OCR 凭据。粘贴、选中列表项均不自动调用百度；回车执行所选 OCR 命令才调用。识别完成不自动复制。

## 当前代码与实现范围

- `src/native-input.ts` 当前只收集文字与输入法事件。
- `PluginInvocation.input` 当前是字符串，Manifest 没有图片 OCR 能力声明。
- `src/credential-settings.tsx` 已有百度 OCR 配置入口；`src-tauri/src/credentials/providers.rs` 已有令牌认证和 OCR scope 验证。
- `credentials.baiduOcr` 已在权限枚举中，但当前公开 Runtime 没有百度 OCR 业务方法。保存配置不等于插件已经获得服务授权。
- 现有 `mainResult` 和 `defaultAction: {type: 'copyText', text}` 可以承载识别结果与第二次回车复制。

本任务是用户明确指派的主程序开发：可以扩展宿主、SDK 合同和 CLI 校验。为完成首版七步闭环，同时交付一个百度 OCR 插件；插件业务代码保留在自身包内。插件部分遵循 `skills/uipilot-public-plugin/SKILL.md`，参考最小结果插件 `com.uipilot.demo-return`，正式插件不使用 demo 名称。

本版聚焦 Windows 主启动器、单张剪贴板图片、主列表结果。文件拖放、多图、PDF、截图工具、Panel/子窗口图片输入及其他 OCR 供应商不在本版范围。

## 方案选择

推荐“宿主图片输入 + 声明式插件匹配 + 宿主百度 OCR 服务 + 轻量结果插件”。图片入口可供后续 OCR 插件复用，凭据沿用现有管理边界。

另外两种方式不采用：将百度识别直接做成唯一内置动作，会偏离用户要求的 OCR 插件列表；让插件自行读剪贴板并保存百度凭据，会重复配置，并使插件收到的图片可能与用户粘贴时不同。

## 主界面交互

- 仅在主启动器输入框获得焦点且用户发生粘贴动作时检测图片。普通文字粘贴和输入法行为保持原语义。
- 优先接收粘贴事件提供的图片；Windows 原生读取只作为本次明确粘贴动作的补充，并绑定当次剪贴板版本，禁止轮询剪贴板或稍后读取另一张图。
- 图片验证成功后，输入区显示紧凑缩略图和具有可访问名称的移除按钮；保持现有 44px 输入容器和 60px 搜索区域基线。
- 只保留一张图片。新的有效图片替换旧图片；损坏或超限图片显示错误，保留原有效图片。
- 保留现有文字，允许文字筛选 OCR 插件名称。图片存在时只列出匹配的 OCR 命令，不混入应用、网页等普通搜索结果。移除图片后恢复文字搜索。
- 列表只枚举已安装、启用、兼容并显式声明 OCR 图片能力的插件命令。初版“百度 OCR”为首选；多个插件时上下键切换。无匹配项时显示“没有可用的 OCR 插件”。
- 缺少所需授权或百度配置不可用时，条目保留并显示不可执行原因；沿用设置中的权限与配置入口，不静默授予权限。
- Enter 执行当前插件后显示“正在识别…”，保留图片。请求进行中忽略重复 Enter，不排队、不重复计费。
- 完成后选中一条识别结果，结果详情显示可滚动的完整纯文字并保留换行；不能把识别文字解释为 HTML 或 Markdown 指令。结果标题可截取摘要，但复制内容必须是全文。
- 结果的默认动作是复制全文；右下 Ctrl+K 操作菜单显示复制入口。用户重新按下 Enter 才复制，按键长按产生的 repeat 不能跨状态触发复制。
- 复制成功显示“已复制”，后续隐藏与图钉行为遵循现有普通复制结果规则；复制失败保留结果供用户重试。
- 无文字显示“未识别到文字”，不提供复制空字符串的动作，也不覆盖剪贴板。
- Esc 先遵循现有模态/操作菜单关闭优先级；从 OCR 请求、结果或错误返回图片插件列表并使旧请求失效；在图片插件列表再次 Esc 移除图片，之后遵循普通隐藏规则。
- 双主题、键盘焦点、状态栏、图标及布局遵守 `docs/ui-guidelines.md`。

## 宿主与插件合同

以下是本次新增合同的设计名称，批准后同步 Rust、前端 DTO、SDK 类型、文档、Schema 和 CLI，不能只新增前端显示字段。

- 命令新增可选 `inputCapabilities: ["image.ocr"]`；省略时保留现有文字行为。第一版只允许 `submit + mainResult` 命令声明它。
- OCR 匹配以能力声明为准，不按插件名称、命令名称或 `credentials.baiduOcr` 权限猜测。
- `PluginInvocation.input` 保持字符串，另增可选只读 `image` 描述符：`id`、`mimeType`、`width`、`height`、`byteLength`。没有图片时省略字段。
- `image.id` 是宿主分配的不透明引用，绑定当前启动器图片版本、插件身份、插件代际及请求上下文；不是文件路径或任意文件读取入口。
- 有图片的 OCR 命令不因文字为空而被 `inputRequired` 拦截；图片是该命令的有效必需输入。无图片时不调用 OCR，显示“请粘贴一张图片”。
- 新增请求绑定的 `api.services.baidu.ocr({imageId})`，返回只读 `{text, lines}`，`text` 按供应商返回顺序以换行连接。只接受当前请求绑定的图片。
- 首版不向插件暴露宿主文件路径、任意剪贴板读取或图片枚举方法；未来其他供应商的图片读取/调用能力独立扩展。
- 百度 OCR 服务需要当前有效的 `credentials.baiduOcr`、`network.https` 授权以及 `aip.baidubce.com` 主机声明；复制仍需 `clipboard.write`。
- 最低宿主版本随新增能力发布，旧宿主明确拒绝依赖新能力的插件；不修改 API/schema 主版本，不让旧插件被动获得图片访问。

## 图片生命周期与异步顺序

- 宿主在内存中保存当前图片快照，校验实际格式与尺寸；缩略图是派生预览，识别使用同一快照的图像内容。
- 第一版采用保守产品上限：PNG/JPEG/BMP，编码输入最多 8 MiB，解码最长边最多 4096px、最多 1600 万像素；标准化后 PNG 最多 3 MiB。此为项目限制，不宣称是百度服务的最大额度。
- 标准化失败或超限给出明确错误，不静默降低图片清晰度。解码/编码放在后台并受上述资源边界约束。
- 图片暂存不写入插件存储、日志或新建永久历史；既有独立剪贴板历史功能不因本次入口改变。
- 导入完成时重新检查启动器会话与导入序号：A 导入未完时粘贴 B，A 的迟到结果不得覆盖 B。
- 替换/移除图片、退出图片模式、隐藏主窗口、插件禁用/卸载/更新时，相关图片引用、请求与结果动作失效；释放预览及不再使用的图片内存。
- 请求结束前后均复核上下文。A 识别中替换为 B，即使 A 返回成功也不能覆盖 B；退出后迟到响应不能重新打开窗口。
- 服务授权撤销或凭据修改使旧请求失效。已发送的远端请求无法保证撤销，但不得继续发布或复制过期结果。

## 百度服务与凭据

- 复用现有设置中已保存且启用的 `baiduOcr` 配置；不读取或展示用户密钥明文，不为插件新增一套密钥设置。
- 默认拟采用百度“通用文字识别（标准版）” `general_basic`，以截图提取普通文字为目标；本版不增加精度选项。
- 服务请求使用宿主保存的 API Key / Secret Key 获取访问令牌，再通过 HTTPS 表单提交图片。插件只收到识别文字，不收到密钥、令牌或供应商原始响应。
- 固定官方服务主机与路径，禁止请求重定向；复用既有网络授权、限流、超时、响应大小和脱敏错误机制。图片业务请求单独设置有界大小，不能为了上传图片放宽所有插件通用网络请求限制。
- 第一版不跨请求持久化访问令牌。每次识别至多一次认证、一次 OCR 请求；失败由用户显式重试，不自动重试 OCR。
- 鉴权失败、未启用配置、未授权、额度不足、超时、网络失败、无文字和坏响应要有不同状态；不得把配置验证成功当成识别额度可用的证明。
- 识别全文或序列化结果超出现有主结果合同上限时，明确报结果过长，不能截断后冒充全文复制。

接口依据：百度官方 [Python SDK](https://github.com/Baidu-AIP/python-sdk/blob/master/aip/ocr.py) 定义标准版 `general_basic` 端点；现有宿主 `credentials/providers.rs` 定义凭据字段及认证方式。供应商请求细节在实现时以官方 API 文档与契约测试核对，不使用真实密钥作为自动测试数据。

## 插件交付

- 新建 `examples/public-plugins/com.uipilot.baidu-ocr/`，显示名称“百度 OCR”，命令 `baidu-ocr`，Windows、submit、mainResult。
- Runtime 接收 `invocation.image.id`，调用宿主百度服务，返回全文详情和 legacy `copyText` 默认动作。
- 插件处理能力缺失、服务错误和无文字；SDK 类型测试覆盖新描述符和服务签名，Node 测试使用假服务。
- 宿主实现与插件实现分阶段验证；无需因当前 API 缺口另建阻塞的宿主能力请求，因为用户已明确授权本任务开发主程序能力。

## 验收

1. 原生 Windows 截图 Ctrl+V 可见缩略图与 OCR 插件列表，粘贴时没有外部 OCR 请求。
2. 首选百度 OCR，Enter 恰好执行一次识别；返回文字后必须再次按下 Enter 才复制全文，换行保持。
3. 普通文字粘贴、输入法、普通搜索与已有插件命令回归通过。
4. 多个 OCR 插件可选择；无插件、插件禁用、不支持的平台、权限不足、配置失效均正确反馈。
5. 无文字与失败不覆盖剪贴板；复制失败可再次尝试。
6. 连续粘贴、重复回车、识别途中换图、清除、Esc、隐藏、插件更新、撤权和凭据修改的旧响应不能污染当前状态。
7. 损坏/超限图片、假 MIME、陌生或过期图片 ID、跨插件引用被拒绝；日志和错误不包含图片、密钥或令牌。
8. 前端、Rust、CLI Schema、SDK 类型和插件单元测试覆盖各自合同；Light/Dark 和真实主窗口键盘流程单独验收。
9. 真实百度识别使用用户选择的测试图片，经现有配置与权限完成一次，单独记录结果；离线测试通过不等于真实服务已经验收。

## 设计自检

已核对：七步顺序与默认百度选择一致；没有粘贴即上传、自动复制或凭据下发；配置与权限区分；替换图片和迟到响应有明确归属；单图、格式、结果长度和失败均有边界。本文为已批准设计，不表示上述能力已经实现。
