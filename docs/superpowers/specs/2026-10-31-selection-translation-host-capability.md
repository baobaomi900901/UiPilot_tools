# 划词翻译：宿主能力请求

2026-11-01 更新：用户已要求兼容复制、缓存并有条件恢复原剪贴板，同时处理 UiPilot 与 Win+V 临时历史；以下首版 UIA-only 限制由 [新的兼容设计](2026-11-01-selection-copy-compatibility-design.md) 替代。保留首版文字作为实现演进记录。

## 用户需求与范围

用户在其他 Windows 应用中选择文字，按 Alt+A，由 UiPilot 打开“翻译”插件，将本次选中文字填入参数输入框并自动提交。保留原来的手动 `/translate` 方式，沿用主界面结果列表，不新增悬浮翻译窗口。本轮继续使用有道服务，不接入 OCR 或 DeepSeek 业务。

状态：用户已回复“继续”，确认本轮包括宿主开发，现按方案实施。新增取词授权默认关闭，实际授权和密钥仍由用户管理。

## 当前 API 缺口

- `src-tauri/src/command_hotkeys.rs` 已有宿主命令快捷键注册、冲突和启停管理。
- `src/launcher-core.ts` 的 `commandHotkeyEntry` 以空参数激活命令；需要输入的插件停留在待输入状态。
- `docs/plugin-sdk/uipilot-plugin-api-v1.d.ts` 的 `PluginInvocation.input` 可接收文字，但没有外部应用选区读取能力，也没有快捷键取词入口。
- `files.openText` 是用户选择文件后导入文本；`clipboard.read` 仍未开放，剪贴板历史权限也不代表读取当前选区。现有能力不能满足本需求。

## 方案比较

1. 推荐：宿主管理一次性选区捕获、快捷键和命令投递，翻译插件继续处理 `invocation.input`。与现有权限、生命周期和快捷键冲突机制一致。
2. 仅要求用户先复制，再进入翻译：实现较少，但不符合选中后直接 Alt+A 的交互。
3. 插件自行监听全局键盘并模拟复制：当前 API 不支持，不为此开放任意键盘监听或输入能力。

## 建议宿主行为

1. 为“翻译”提供独立的“划词翻译快捷键”，初始建议 Alt+A；可在插件详情修改、清除。保留原有启动快捷键语义，冲突时显示状态，不覆盖其他绑定。插件禁用、删除时注销该绑定。
2. 按键触发时先记录原前台窗口和当前操作身份，读取当前选区后再显示主窗口，避免焦点切换破坏选区。只在用户主动触发时读取，不后台监控选择。
3. 首版通过 Windows 可访问性选区只读获取。实现审查证实，单次复制的剪贴板序号不能可靠区分本次模拟复制与同一应用中紧随其后的用户复制，因此不启用复制兼容路径，不读写系统剪贴板。应用未提供可读取选区时给出手动输入提示。保留 Unicode、空格和换行；不能宣称支持所有应用。
4. 没有选择、空白文本、超出翻译输入上限、读取超时或目标切换时不发出翻译请求，在应用内显示明确提示。输入保持 Unicode、换行和原始空格，不静默截断超过 8192 UTF-8 字节的选区。
5. 以稳定插件 ID 和命令身份投递，使用用户当前命令名称展示，避免命令重名或更名后进入错误插件。主界面显示参数后只自动提交一次，不通过模拟粘贴/回车操作自己的输入框。
6. 连续触发以最新操作为准；用户编辑、关闭界面、禁用插件或撤销相关权限会使旧捕获及晚到结果失效。按键长按不重复消费 API 额度。
7. 建议增加独立的“读取选中文字”授权，在插件详情和权限页管理；首次未授权时引导用户开启，不因有道或网络授权自动获得。选中文字只交给本次明确选择的插件，不增加任意剪贴板读取 API，不记入诊断日志。
8. 自动提交沿用现有有道服务、网络权限及配置检查。缺失权限或关闭配置时显示对应提示，不自动开启服务、不自动重试。

## 2026-11-01 兼容性排查

用户实测浏览器、Codex 输入框、记事本能取词，微信输入框等应用失败。当前捕获器只读取焦点控件自身的 UIA TextPattern。开发构建增加本机 `uipilot-selection-<PID>.log`，仅记录阶段、数值错误码、控件类型、进程 ID、选区数量和耗时，不记录文字、窗口标题或服务返回的错误描述。

用户主动复测的微信记录确认：目标进程为 `Weixin`，焦点控件类型是 `50032`（Window），获取 TextPattern 没有得到接口，最终返回 `selection_unsupported`（本次耗时 525ms）。这说明当前路径得到的是外层窗口，未获取到输入框选区；不能推广为该应用所有控件永久不支持 UIA。

随后用户确认同时处理 UiPilot 与 Win+V 历史，并进一步要求缓存、恢复原剪贴板；当前执行的是本文页首链接的新设计，先前“不恢复”的建议已被替代。

已修正失败反馈：失败事件阻止主界面的默认搜索覆盖提示；有有效翻译命令时进入空的翻译输入框，保留失败原因，不发起空参数预览或翻译。用户编辑后恢复普通手动翻译流程，晚到的命令解析不得覆盖用户的新输入。

## 验收检查

- 浏览器正文、记事本及编辑器中选中中英文，Alt+A 后正确填入并只翻译一次；手动翻译仍可使用。
- 多行、Unicode、空白和长度边界正确处理；无选区时不翻译旧剪贴板内容。
- 选区捕获发生在主窗口抢占焦点之前；捕获期间用户切换窗口则停止原操作。
- 读取选中文字、有道和网络授权分别关闭时，得到准确提示且不调用服务。
- Alt+A 被占用、快捷键清除或修改、插件更名/禁用/重载后，绑定及目标行为正确。
- 长按、快速重复触发、捕获期间输入或隐藏主窗口均不产生重复请求或覆盖新输入。
- 原剪贴板文本、图片和文件列表保持不变；取词没有模拟按键或剪贴板写入。未提供 UIA 选区的应用返回可理解提示，不启用无法证明归属的复制恢复路径。
- 自动化测试使用模拟选区和服务，不读取用户真实选区或调用真实有道 API；实机输入与复制验收由用户主动触发。
