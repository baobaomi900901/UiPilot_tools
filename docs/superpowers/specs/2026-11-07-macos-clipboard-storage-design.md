# macOS 私有文本历史与授权生命周期

本单元接续[共用基础](2026-11-07-macos-clipboard-foundation-design.md)和[文本观察器](2026-11-07-macos-clipboard-observer-design.md)，实现原计划 Task 10.1 的文本历史介质与授权协调器。宿主仍不启动历史服务，不扩大 SDK 权限或插件平台声明，不读真实剪贴板。图片、文件、复制、粘贴和产品 UI 后续单独接入。

## 共用业务与容量

沿用 `HistoryDocument`、摘要 DTO、文字预览与文字指纹。将历史变换中与系统无关的部分提取为共享函数；Windows 调用相同变换，原来的图片落盘、路径可用性检查、文件写入和格式校验行为保持不变。本轮不以 Mac 的限制静默加强 Windows 已有文档校验。

历史最多 50 条，按 recency 降序。相同文本已在首项时不改变 revision；命中较旧项只更新 recency 和 revision，保留原 ID 与 capturedAt。新项使用从不回收的十进制 ID；删除和清空不重置计数器。溢出必须报错且不提交候选状态。摘要仅公开既有预览，不新增完整正文或路径字段。

Mac 当前只接纳文本，每条最多 1 MiB，序列化后的 index 最多 8 MiB。在共同的 50 条限制后，如超过序列化预算，继续逐出最旧项；若最新一项仍不能满足预算则失败。此为 Mac 内部文本存储预算，不宣称 Windows 具有相同字节预算，也不修改公开 SDK。已载入文件及单次新增内容均先限长，避免先构造无界候选再检查大小。

## 介质与文件边界

宿主提供可信 app data 绝对路径；不接受插件提供任意路径。复用 manifest 的 plugin ID 校验并要求单一普通路径组件，在任何插件目录操作前拒绝非法 ID。专用目录为 `app_data/clipboard-history/<plugin ID>`，正文仅存在各插件的固定 index 文件中，不写备份或正文日志。

路径按组件以 nofollow 打开，后续操作相对于持有的目录 FD。验证本地文件系统、当前用户所有权和目录身份。app data 不能让其他用户写入且不接受扩展 ACL；专用根和插件目录必须为 0700 且无扩展 ACL，index 和 staging 必须是当前用户的 0600 普通单链接文件且无扩展 ACL。已有不安全对象直接拒绝，不能通过 chmod 接管其他文件。权限不是加密，不声称对 root 或任意同用户恶意进程构成隔离。

目录加排他非阻塞锁，避免两个协作实例同时管理同一历史；关闭 store 显式解锁再释放 FD，不能依赖临时继承的文件描述符何时关闭。协调器记录初次验证的 app data 和专用根身份，即使尚无活跃 store，后续授权也不能静默采纳替换后的目录；身份检查须先于插件子目录创建，根缺失时不在当前实例中重建。操作前复验具名路径与持有 FD 的对象身份；路径被替换、链接、改权限或加 ACL 后拒绝。正常操作只清理本次创建且身份匹配的 staging。重新打开时，在获得排他锁后，可以丢弃专用目录中保留名称 `index.pending` 的遗留 staging：先 nofollow 打开并验证普通单链接、当前用户、0600、无 ACL、本地文件系统及持有/具名对象身份，再 unlink 并同步目录。不读取或恢复其正文；不安全 staging 拒绝且保留，不处理其他文件，也不递归删除目录。这样提交前崩溃不会使后续重启永久不可用。无 current 才视为空历史；损坏或不支持的 current 保留原文件并返回固定错误，不默默重置或覆盖。

读取先检查文件类型、身份和长度，再限量读取。Mac 文档严格验证 schema、ASCII 规范十进制、唯一 ID/rank/fingerprint、next 计数大于已用最大值、最多 50 条、text-only、字段大小及文本指纹/预览一致性。授权不会从 index 恢复。

## 原子提交与错误

在同一私有目录排他创建 staging → 写入并同步 → 复验目录/文件边界 → rename 为 current → 同步目录。仅完成提交后更新内存状态并报告成功。

rename 之前失败：保持原 current 与内存状态，清理自身 staging。rename 之后同步或复验失败：报告内部 CommitUncertain，当前 store 进入不可继续读写的状态，不能宣称磁盘已回滚；关闭并重新打开后，以经过严格校验的 current 恢复。不能自动回放旧快照覆盖可能已提交的新记录。固定业务错误不附带正文或路径。同步成功表示系统接受同步操作，不额外承诺断电恢复测试已经通过。

## 授权、读取批次与撤回

`MacHistory::open` 只打开私有介质；不创建 observer。authorize 仅由未来宿主已核准的权限状态驱动。活跃 ID 的重复 authorize 幂等；撤回后再次 authorize 创建全新、不可复活的 generation。每个授权 token 绑定协调器实例、插件 ID 与 generation。token 和捕获批次不持有 store 或 FD，避免旧票据阻止撤权后的重新打开。

读取前必须取得已有授权 generation 的快照；没有活跃授权时不能开始正文读取。捕获批次只能消费一次。history 在 observer 的会话准入内核验批次所属实例及各原有 generation，再完成受保护写入；不能收到旧 event 后临时抓取新授权。授予新插件不会让它收到授予前已开始的读取，撤回再授权也不会让旧批次复活。

首个存储单元曾提供显式 `bind_capture` / `ingest(event, batch)` 接口和消费时刻，尚未接入 observer。后续[采集接线规格](2026-11-07-macos-clipboard-collection-design.md)取代这些临时接口：生产只接受绑定批次、会话、结果和读取前观测时间的密封事件，并在授权集合改变时重建基线。不能仅在读取后的回调里临时绑定授权。同一文本再次命中仍保留首次 capturedAt。

snapshot、查询、删除和清空同样要求当前有效 token；无授权、跨实例或过期请求必须在访问插件历史前拒绝。查询沿用 Windows 的 512 Unicode scalar 上限、去除首尾空白、大小写不敏感连续子串和最近优先顺序；通过授权后，超限查询应得到 InvalidQuery，不能伪装成存储故障。撤回保留已存历史，授权内显式 clear 才清空内容。撤回先关闭 generation 的新准入，随后在状态锁外等待已准入操作结束；返回后不得再有该 generation 的读写，且其 store 文件锁已释放。相同 ID 的撤回和重授权需串行，不能让旧写入越过新授权完成。其他仍授权的插件保持可用。

shutdown 永久关闭协调器、退役所有 generation 并等待在途操作结束，随后释放存储句柄；之后授权、读取准入与 ingest 均拒绝。重开协调器从无授权开始，旧实例 token 不能用于新实例。协调器不拥有 observer，不在授权锁内 join 原生线程；整体退出应先退役采集准入，再按观察器合同在业务锁外停止线程。原生读取许可的独立排空顺序见采集接线规格。

## 验收

默认测试只使用合成内容和本轮创建的临时目录，不访问个人历史或通用剪贴板。

- 共同语义：相同文本去重、50 条淘汰、首次时间保留、ID/revision/recency 溢出、删除和清空后不复用 ID；Windows 使用的共享变换也在 Mac 运行合同测试。
- Mac 文档：1 MiB 文本与 8 MiB 文件边界、预算淘汰、重开保留、损坏/重复/非法计数/错误摘要与指纹/非文本 payload 拒绝。
- 文件边界：非法 ID 无目录副作用、目录/文件链接和硬链、权限或 ACL 变化、目录替换、重复打开、遗留 staging；拒绝时不得改动替代目标。
- 提交：注入 rename 前失败保留旧内存和 current；rename 后失败返回不确定并拒绝继续读写，重开校验当前记录。
- 授权时序：绑定批次后新增授权不接收旧内容；撤回后迟到 event、重授权旧批次、跨实例 token 和重复消费全部拒绝；撤回等待已准入写入完成，另一插件仍可用；shutdown 排空后旧票据失效且重开默认无授权。

全仓自动验证和 Mac 普通/Find 预览编译需通过。Windows 原生回归另列；本轮不将基础单元完成等同于 Task 10.1、插件跨平台或实机授权验收通过。
