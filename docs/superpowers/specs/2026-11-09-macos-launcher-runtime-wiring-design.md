# macOS 主程序与插件运行协调

在安装管理、RuntimeDataBinding 和 MainResultPublisher 之上接入主程序查询生命周期。不依赖 Apple 开发证书的范围是 Host 调度、调用数据、取消与最终结果发布。生产传输适配器尚不可用，`plugins=false` 保持；不能以 ad-hoc 子进程、普通 pipe 或测试替身替代签名 XPC 的对端身份和沙箱证明。

## 主程序路径

复用可信 main 的 search_apps 调用者验证和主 ResultRegistry。运行协调器与管理 IPC 共用同一个 ManagementState / MacPluginLifecycle，不能另开库存、另持同一文件锁或复制授权快照作为第二权威。默认构造不访问磁盘、不启动进程；关闭的执行入口直接返回未处理，原应用、计算与 Find 搜索行为保持。

内部可用适配器只按已验证 manifest 的明确命令选择已安装且启用的 mainResult 插件。Live 随匹配查询执行，Submit 仅在现有 search_apps 的 submit=true 时执行，不把普通键入等同于用户提交。Host 生成 request ID、command ID 和环境，代码来自安装快照，普通设置及 storage 沿用绑定的数据服务；不接受前端路径、代码或插件自报的授权。保留内置命令优先级和必填输入边界，不因输入前缀而运行未确认的 command。

环境使用真实宿主主题选择和 UTC RFC3339 时间；旧单命令调用省略 commandId，多命令才传稳定 ID。生产工厂没有可用传输，故本轮没有向前端发送插件结果，也不修改前端能力过滤。受控适配器验证的是 Host 调用链，正式渲染、命令补全/稳定身份路由和 Panel/Window 接线仍属于后续范围。

仅当适配器可用且查询是可候选的明确插件命令时，才按需重验安装库，支持重启后直接调用。input 保持既有 64 KiB 字节上限并拒绝 NUL；无效输入不得交给传输。关闭状态、普通应用查询和保留内置命令不初始化插件库。

## 生命周期和锁

管理锁只用于库存验证、请求绑定与捕获退休回调；传输执行及数据回调在锁外运行。取消句柄不得依赖 worker 正持有的读循环锁，也不得等待自身的 reply permit。隐藏、退出、新 invocation、更新查询与管理变更关闭旧请求准入；清理只作用于捕获的请求。旧序号、旧 invocation 或迟到 worker 不得取消新请求。

请求在等待管理锁之前的检查不足以授权打开 Runtime。必须在取得同一管理锁后、open_request 可能关闭既有运行时之前再次核对查询所有权；attach 时仍做最终注册检查。回归需固定复现：A 通过外部检查后暂停，B 打开并运行，A 恢复时不得关闭 B。

管理 reset 的通知携带被退休的 epoch。即使通知晚于新 epoch 的请求注册，也只能清理原 epoch。退出同步关闭准入并发出取消；后台排空的存在不等于立即退出前已完成进程回收，正式传输退出验收仍需另行验证。

执行完成必须先获得传输终结证明，再通过原请求的完成票据与实际 MainResultPublisher 发布 SearchResponse。最终写入仍由注册表原子检查查询所有权；失败、超时、撤权、旧响应均不发布部分成功。仅信息型结果允许进入当前路径，复制动作、Panel/Window、真实网络/凭据服务不随本轮开放。

## 验证边界

使用临时私有安装库和受控传输替身测试主程序所用的协调器：已安装设置读取、准确命令及输入、结果 DTO，停用/升级/隐藏/新查询与迟到完成之间的顺序，以及关闭状态零库存 IO。保留权限和结果注册表真实实现，不将替身输出称为真实 JS 或 XPC 实测。编译真实 Tauri 入口并回归现有 Mac 搜索与管理测试。没有启动 GUI、操作个人安装库或系统权限；生产签名传输、完整模块图和同包双端实机验证仍未完成。
