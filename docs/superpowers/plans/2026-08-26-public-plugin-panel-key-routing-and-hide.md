# Public Plugin Panel Key Routing And Hide Implementation Plan

**Goal:** Ship Host `0.3.1` with the approved public panel `hostKeys`, `onHostKey`, `requestHide`, Escape, and explicit-return foreground-restore contracts.

**Architecture:** Extend the manifest and command-result contracts first, then carry the canonical declarations through the launcher into one Rust-owned serial delivery state machine. Keep hide admission, observation, and commit in the panel controller as an epoch/ticket CAS; route every terminal explicit return through one hide-reason-aware lifecycle path.

**Technology:** Rust/Tauri, TypeScript/React, Vitest, schemars/AJV, the public plugin CLI.

## Global Constraints

- Source of truth: [approved design](../specs/2026-08-26-public-plugin-panel-key-routing-and-hide-design.md), especially sections 3 through 10.
- Preserve `schemaVersion = 1` and `apiVersion = 1`; Host version is `0.3.1`.
- Keep `com.uipilot.notes` unchanged. `demo-panel` is only a minimal Host-contract fixture.
- Enforce caller capability before protected state: enqueue is main-only; host-key ack and all hide phases are panel-content-only.
- Never synthesize input or control the user's mouse/keyboard. Real focus acceptance is a user-run manual gate.
- Preserve pre-existing worktree changes and stage only task-owned hunks in overlapping files.

## Global Execution Rules

- Every task follows focused TDD: add a failing test, confirm the intended failure, implement the minimum frozen contract, and rerun the focused tests.
- Each task ends in an atomic local commit. Do not push and do not absorb pre-existing user changes.
- Dependency order: `Task 1 -> Task 2 -> Task 3 -> Task 4 -> Task 5`.

### Task 4: Hide CAS, Escape Arbitration, And Foreground Restore

**Files:** `src-tauri/src/plugin_panel.rs`, `src-tauri/src/commands.rs`, `src-tauri/src/lifecycle.rs`, `src-tauri/src/lib.rs`, `src-tauri/capabilities/plugin-panel-content.json`, `src-tauri/permissions/autogenerated/plugin_panel_request_hide_admit.toml`, `src-tauri/permissions/autogenerated/plugin_panel_request_hide_admit_observed.toml`, `src-tauri/permissions/autogenerated/plugin_panel_request_hide_commit.toml`.

**Dependencies:** Task 3; design sections 3.2, 7, 8, 9, and 10.

- [ ] Expose `requestHide()` as admit -> resolve -> fire-and-forget observed -> always next-macrotask commit; implement the sole capture + `queueMicrotask` Escape arbitration.
- [ ] Implement hide-ticket `Admitted -> Observed -> Committed` CAS, 500 ms Observed fallback, 30 s Admitted reclaim, duplicate/noop behavior, monotonic exhaustion, and epoch/timer invalidation.
- [ ] Introduce `HideReason`; capture HWND+PID on show with Shell-clear and UiPilot-repeat-keep policies; on `ExplicitReturn`, revalidate HWND+PID and best-effort restore after hide without changing an admitted result.
- [ ] Freeze and capability-gate admit, observed, and commit commands; use the same explicit-return path for Escape, requestHide, unsubscribe, timeout, and protocol termination.

**Distinct test coverage:** observed-before-commit and commit-before-late-observed each hide once; rejected/hung observed never blocks scheduled commit; 500 ms versus 30 s phase-specific fallback; stale timer during a new session no-op; sync `preventDefault`/dialog/composition suppress Escape while post-await does not; Shell capture clears, repeat UiPilot show keeps, PID mismatch/Blur skip restore.
