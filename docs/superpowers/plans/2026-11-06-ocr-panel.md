# OCR Panel 双入口实现计划

## 目标与架构

执行[已批准设计](../specs/2026-11-06-ocr-panel-design.md)，把 OCR 改为可从图片列表或 `/ocr` 进入的标准 Panel：左图、右侧可编辑文本、自动识别及显式复制。

宿主维护会话图片和服务授权，插件消费有界图片通知并编排识别。图片列表按能力发现不同插件，原 mainResult OCR 保持兼容。复用翻译 Panel 的 Ready、状态栏、复制与焦点规则。

## 全局约束与执行

- Windows / Rust Tauri 2 / React 19 / TypeScript；Host 0.21.0，API/schema v1；新插件 `com.uipilot.ocr@1.0.0`，名称及命令 `ocr`。
- 每项按 TDD 添加聚焦失败用例，再实施、验证、规格和质量审查；独立原子提交，仅包含本任务改动。共享 dirty 文件由协调者隔离原有差异后提交。
- 同目录独立分支，保留用户已有改动；不重装依赖、不修改用户插件安装状态/授权/凭据。预先备份 dirty diff 和重叠源文件。
- 不使用 Computer Use，不自动调用真实百度；原生验收由用户执行。代码测试使用合成图片、假服务与假剪贴板。
- Cargo 同时只运行一个本任务测试进程；利用同一编译快照完成相关组，避免重复链接。开发 watcher 可能触发重编译，不停止不属于本任务的会话。
- 每项完成后审查再进入依赖项。Task 1 → Task 2 → Task 3 → Task 4 → Task 5；协调者处理跨模块集成。
- 新增公开合同、上限与顺序以设计“新增公开桥合同”“异步与失败行为”为准。

## 内部接口约定

- `open_plugin_panel` / `LauncherClient.openPluginPanel` 在现有 input 内新增可选 `imageId`，将启动器快照交接给新 Panel；省略保持文字/空入口。
- `import_launcher_image` 的 input 新增可选 `panel: { sessionEpoch: U64Decimal }`。省略继续导入启动器；存在时只允许 main 向当前具备图片能力的 Panel 导入，提交时再次核对会话。返回既有 LauncherImage 形状；前端 Panel 路径不把返回图片放回主输入框。
- `PluginPanelCommandResult` 新增可选 `inputCapabilities: readonly ('image.ocr')[]`，无能力时省略，前端 parser 和 Panel snapshot 同步。不得因本扩展拒绝旧命令结果。
- 内容页 `clearImage` 由新增 `plugin_panel_clear_image` 私有 IPC 支持，只授予 plugin-panel，调用包含当前 sessionEpoch 并核对实际内容 WebView。主窗口清除启动器图片不能释放已交接图片。
- 图片通知使用独立宿主事件 `uipilot-plugin-panel-image-changed`；初始/后续 payload 均为设计规定的 sessionEpoch/revision/image。Host 只向当前内容 WebView 发送，并保持 Ready 后顺序。
