# Public Plugin Panel Focus Host Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the no-argument public panel API `window.uipilotPluginPanel.focusHostInput(): Promise<void>` so a live panel can return keyboard focus to its tagged launcher argument input without changing panel state or text.

**Architecture:** The approved [design specification](../specs/2026-08-25-public-plugin-panel-focus-host-input-design.md) governs the request/ack protocol. Rust owns a latest-wins `HostInputFocusTicket`, native focus, timeout, session/caller authorization, and focus-revision CAS; the launcher owns the exact argument input ref and acknowledges actual DOM focus. Bootstrap hides `sessionEpoch` from plugins.

**Tech Stack:** Rust 1.96, Tauri 2.11 multi-WebView commands/events/capabilities, Windows foreground/WebView focus, TypeScript 7, React 19, Vitest 4, checked-in SDK declarations.

## Global Constraints

- Public method name is exactly `focusHostInput()` with no arguments.
- Bootstrap privately supplies canonical decimal `sessionEpoch`; Rust allocates canonical decimal `focusRequestId`.
- Capability-outside callers are rejected; stale capability-matching panel callers resolve as no-op.
- Current native/event/ack/timeout failures reject existing `windowFailed`; stale/superseded/teardown requests resolve as no-op.
- Request latest-wins never advances global `focusRevision`; only confirmed native main focus or `GotFocus` does.
- No controller lock spans native focus, event emission, or frontend acknowledgement waiting.
- No notes plugin or existing plugin business logic changes; no live keystroke stream.
- Real Windows focus validation is manual and never synthesizes mouse or keyboard input.

## Global Execution Rules

- Dependency order is `Task 1 -> Task 2 -> Task 3 -> Task 4`.
- Each task follows focused TDD, produces one atomic commit, and receives independent specification/code review before the next task starts.
- Existing unrelated `src-tauri/src/public_plugins/activation.rs` changes remain unstaged and untouched.
