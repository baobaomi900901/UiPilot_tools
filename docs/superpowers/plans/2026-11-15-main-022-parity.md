# Main 0.22 新能力纳入 macOS 总目标

## 目标与架构

按用户 2026-11-15 的要求，拉取 Windows 主线新功能，并将图片输入、可编辑 OCR Panel、插件文本分享纳入 Win/Mac 能力大致一致及同包插件兼容的完整目标。复用主线共享合同与业务插件，Mac 补原生适配、会话隔离和能力接线；不另做 Mac 专用 OCR 插件，不靠只修改 supportedPlatforms 声称兼容。

本次已完成远端拉取与差异盘点，冻结 `origin/main` = `bccecb134ed06e9692a8322be9d8a9b39e03c4a3`。main 相对共同基线 `40407fa` 新增 32 个提交、203 个路径发生变化；当前 macOS 分支在本轮记录前为 `7433cda`。**尚未把 main 合入当前分支**，未修改本地 main。无工作区改动的 merge-tree 预检发现 11 个冲突文件，后续 Task 1 专项解决；不得将 fetch 或无冲突文件的自动合并视为完整集成通过。

## 技术、合同与约束

目标 Host 0.22.0，API/schema 1，沿用锁定 Rust/Tauri2、React/TypeScript。旧 Mac 已验收包 0.19.0 仍是既有验收基线，版本提升后的兼容必须重新验证。开发分支继续 `codex/macos-port-plan`，只推送该分支，不并入 main。无 GUI 自动化；真实粘贴、焦点、供应商调用和安装由用户完成，合并同类人工检查，只测新行为和必要回归。

上游权威来源固定在上述提交：

- `docs/superpowers/specs/2026-11-06-ocr-panel-design.md`：两种入口、面板与键盘、宿主能力与插件边界、新增公开桥合同、异步与失败行为。
- `docs/superpowers/specs/2026-11-06-plugin-sharing-design.md`：单面板首版、边界与失败行为、宿主流程、调用与数据边界；其最终版本已替代旧双面板事务/受限准备运行时方案，不重新实施废弃设计。
- `docs/plugin-sdk/public-plugin-v1.md`、`uipilot-plugin-api-v1.d.ts`、`uipilot-plugin-v1.schema.json`：图片与分享合同。
- `docs/plugin-sdk/plugin-examples.md`：业务插件/基座参考/Demo/验收夹具分类，旧 note 删除，三个 Demo 源码目录调整但 pluginId 保留。

这些文件部分尚只在拉取的 Git 对象中，集成后进入当前树。Windows 设计当前明确仅 Windows；开放 Mac 前补 Mac 平台扩展设计，保留相同数据/失败合同并明确原生差异。没有开发者证书不阻碍纯模型、合同、fake-service、适配代码和内部构建；生产隔离身份、签名验证和插件实际开放继续受原发布门槛约束，不绕过原生隔离。

## 新增范围和当前状态

| 能力 | main 已有内容 | 纳入 Mac 的工作 |
| --- | --- | --- |
| 图片输入 | 明确粘贴动作接收图片、临时缩略图、能力匹配与请求专用图片引用 | NSPasteboard 明确动作读取、有界解码/预览、IME/键盘、图片归属和生命周期；不得后台采集任意图片 |
| OCR | `/ocr` 空 Panel 与先粘图双入口；编辑全文、清图、换图、重试、复制；百度宿主服务 | 同一插件接入 Mac Panel、Keychain 凭据/网络服务与权限撤回；A→B→C 只允许最新图片发布 |
| 文本分享 | 当前编辑文本经操作菜单选接收者；翻译接收后自行处理；单一活动 Panel | Mac ⌘K、选择器与原生内容显示/焦点，精确文档一次领取；失败留目标，禁止自动回源/重发 |
| SDK/交付 | Host 0.22、OCR 1.1.0、翻译 1.5.0、校验器/CLI/示例更新、Runtime 文档就绪修复 | 版本/清单/生成器同步，Mac 内部运行器与模块装载对齐，原管理和升级数据保留 |

main 当前统计 17 个参考包：3 个声明 windows+macos、14 个仅 windows。OCR 替代旧独立窗口 note 后总数仍为 17，不能拿同样的分母掩盖包集合变化；同包双端生产实测仍为 0/17。OCR/翻译当前均仅声明 Windows，main 文档中真实安装、百度/有道及原生交互仍有待人工项，未继承为本分支通过证据。
