# UiPilot UI 规范

本规范是 UiPilot 宿主界面、内置功能和公开插件 UI 的统一视觉与交互基线。目标是保持 Raycast 式的紧凑、安静、键盘优先体验，同时完整支持 Light 与 Dark 两种主题。

## 1. 使用范围与优先级

以下任务在设计或修改 UI 前必须阅读本规范：

- 主启动器、设置页、内置功能和内置管理面板。
- 公开插件的 Panel、子窗口、图标和状态展示。
- 会改变布局、主题、组件状态、键盘交互或可访问性的修复。

发生冲突时按以下顺序判断：

1. 功能与 SDK 合同、用户明确需求。
2. 本规范定义的语义和交互规则。
3. `src/ui-theme.css` 中的当前 token 值。
4. 同类现有界面，优先参考主启动器、设置页、`/notes`、`/quicklinks` 和 `/clipboard-history`。
5. Raycast 视觉语言只作为参考，不覆盖 UiPilot 的双主题、Windows 行为和插件安全边界。

## 2. 设计原则

### 2.1 工作界面优先

- 第一屏直接呈现可操作界面，不增加营销区、装饰性大标题或说明卡片。
- 信息密度保持紧凑，内容按搜索、列表、详情、状态的工作流组织。
- 使用完整宽度的区域、分隔线和表面层级组织界面；卡片只用于真正独立或重复的项目。
- 不把卡片嵌套在卡片中，不为页面区块增加悬浮卡片效果。

### 2.2 Raycast 式克制

- 通过背景表面阶梯和 1px 细边框建立层级，不使用装饰性投影。
- 圆角小而一致，主要使用 6px、8px 和 10px。
- 主色只用于主要动作；蓝、绿、黄、红用于图标分类或语义状态。
- 不使用装饰性渐变、光斑、模糊色块或大面积单一强调色。
- 动效只反馈状态变化，默认使用 `120ms ease`，不得造成布局位移。

### 2.3 Light / Dark 对等

- 所有界面必须同时支持 Light 与 Dark，不把 Dark 样式简单反相得到 Light。
- 两种主题中的组件角色必须一致：主按钮始终使用 `primary` 背景与 `primary-foreground` 文字。
- 不在组件 CSS 中写死用于主题结构的颜色。宿主使用 `--uipilot-ui-*`；插件使用宿主注入的 `--uipilot-color-*`。

## 3. 主题与颜色

宿主 token 的值以 `src/ui-theme.css` 为唯一事实来源。实现时按语义选择 token，不根据当前十六进制值选择 token。

| 角色 | 宿主 token | 用途 |
| --- | --- | --- |
| 页面底色 | `--uipilot-ui-background` | 启动器、设置内容、Panel 主画布 |
| 主表面 | `--uipilot-ui-surface` | 侧栏、状态栏、独立容器 |
| 抬升表面 | `--uipilot-ui-surface-elevated` | 输入框、次级按钮、悬停状态 |
| 选中表面 | `--uipilot-ui-surface-card` | 选中行、未读行、图标底板 |
| 主文字 | `--uipilot-ui-foreground` | 标题、主要内容、活动状态 |
| 正文 | `--uipilot-ui-body` | 辅助正文 |
| 次要文字 | `--uipilot-ui-muted-foreground` | 占位符、元数据、弱提示 |
| 细边框 | `--uipilot-ui-border` | 区域分隔、普通控件边框 |
| 强边框 | `--uipilot-ui-hairline-strong` | 焦点、选中、需要更强区分的边界 |
| 主要动作 | `--uipilot-ui-primary` | 主按钮、关键操作 |
| 主要动作文字 | `--uipilot-ui-primary-foreground` | 主按钮文字与图标 |
| 危险状态 | `--uipilot-ui-destructive` | 删除、错误、破坏性操作 |
| 成功状态 | `--uipilot-ui-icon-green` | 启用开关、成功反馈 |
| 滚动条 | `--uipilot-ui-scrollbar` | 宿主虚拟滚动条和 OverlayScrollbars |

蓝、绿、黄、红及其 soft 变体用于图标底板和语义状态。它们不得取代主要动作颜色，也不得大面积铺满页面。

公开插件只能依赖宿主公开注入的变量：

```css
--uipilot-color-background
--uipilot-color-surface
--uipilot-color-text
--uipilot-color-text-muted
--uipilot-color-border
--uipilot-color-accent
--uipilot-color-danger
--uipilot-font-family
```

插件可用 `color-mix()` 派生悬停、选中和柔和状态，但必须提供兼容回退值，并在两个主题下验收。

## 4. 字体、图标与几何

### 4.1 字体

- 宿主字体使用 Inter；中文回退使用 `Microsoft YaHei UI`，之后使用系统无衬线字体。
- 全局启用 `font-feature-settings: 'calt', 'kern', 'liga', 'ss03'`。
- `letter-spacing` 固定为 `0`，字体大小不随视口宽度缩放。
- 紧凑界面的默认层级：12px 状态与元数据、13px 标签、14px 正文与列表标题、16px 页面标题。
- 常规字重使用 400，标题、选中项和按钮使用 500；仅在确有层级需要时使用 600。
- 紧凑面板和设置页不使用 hero 级字号。

### 4.2 图标

- 命令和工具按钮优先使用 Lucide 图标；不得手绘已有的通用符号。
- 仅图标按钮必须有可访问名称，并为不熟悉的图标提供 tooltip。
- 功能图标使用对应语义色与 soft 背景；图标底板默认 8px 圆角。
- 空状态图标必须表达当前对象，例如目录使用空文件夹盒子，链接使用链接图标。

### 4.3 尺寸与圆角

- 4px 是基础间距单位；常用间距为 4、8、12、16、24px，可使用 6、10、18px 适配紧凑布局。
- 6px 用于列表项、tag、keycap 和紧凑按钮。
- 8px 用于输入框、常规按钮和图标底板。
- 10px 用于对话框、空状态图标容器和较大的独立工具容器。
- 控件应有稳定高度、宽度或网格轨道，悬停、加载、图标和动态文字不得推动布局。

## 5. 宿主界面布局

### 5.1 主启动器

- 搜索区域外边距为 8px，输入容器高度为 44px。
- 查询输入框使用抬升表面、1px 强边框和 8px 圆角，不使用投影。
- 结果行最小高度为 53px，水平内边距 10px，圆角 6px。
- 当前选中行使用 `surface-card`，必须与默认背景形成清晰差异。
- 分组标题与底部状态栏使用 12px 次要文字；状态栏保持单行并截断溢出内容。

### 5.2 设置页

- 顶部标题栏与内容区之间使用 1px 分隔线。
- 左侧导航宽度为 144px；所有 tab 使用同一 DOM 结构、内边距、圆角和活动态。
- 活动 tab 使用 `accent` 背景与主文字，不显示额外 ink bar。
- tab 内容层的左内边距为 0；实际页面内容统一使用 `18px 24px` 内边距。
- 普通内容最大宽度为 640px，表单最大宽度为 560px。
- 通用、消息、插件三个 tab 必须共享相同的标题、滚动、内容起点和导航状态规则。
- 插件启用开关的 checked 状态使用成功绿色。

### 5.3 Panel 类型界面

- 宿主管理顶部命令输入区：总高度 60px、外边距 8px、输入容器高度 44px。
- 命令 tag 高度为 30px，使用比输入容器更明显的背景和强边框；tag 与输入框必须一眼可区分。
- Panel 内容区顶部使用 1px 分隔线。
- 目录或分类侧栏默认宽度为 220px，使用主表面和右侧 1px 分隔线。
- 侧栏工具栏高度为 48px；详情标题栏高度同样为 48px。
- 列表内容右侧至少保留 14px 空间给虚拟滚动条。选中项的边框和背景不得覆盖滚动条。
- 进入管理型 Panel 时默认不选择第一项；只有命令参数明确指向某项或工作流明确要求时才恢复选择。
- 主输入值为空时始终显示领域明确的占位符，例如“搜索目录”或“搜索快速链接”。
- 未选中项目时，详情区显示与领域一致的空状态，不显示无关图标。

视觉一致是合同，不要求跨插件共享组件。内置功能和每个公开插件可以各自维护 HTML/CSS，但相同角色必须遵守相同尺寸、token 和状态规则。

## 6. 组件与状态

### 6.1 输入框

- 默认使用抬升表面、1px 边框和 8px 圆角。
- 占位符使用次要文字颜色，输入为空时不得省略占位符。
- `:focus` / `:focus-within` 使用强边框；除主命令输入外不增加装饰性光圈。
- 搜索、筛选和命令参数使用明确的 `aria-label`，不要只依赖 placeholder。

### 6.2 按钮

- 主要按钮：`primary` 背景、`primary-foreground` 文字，Light 中为深底浅字，Dark 中为浅底深字。
- 次级按钮：抬升表面、普通边框、主文字；hover 提升到选中表面并加强边框。
- 危险按钮：透明背景、危险色文字与边框；确认后才执行破坏性操作。
- 工具命令使用图标按钮；文字按钮保留给“保存”“重新录制”“删除”等明确动作。
- disabled 状态保持可辨认，但不得比普通次要文字更抢眼。

### 6.3 列表与选择

- hover、键盘焦点和选中态必须可区分，选中态的背景对比高于 hover。
- 列表项边框应使用 inset 或预留滚动条空间，不能改变列表项尺寸。
- 列表文字使用单行截断或明确换行规则，长单词不得突破容器。
- 删除按钮默认弱化，只在 hover、focus 或明确操作区提高可见性。

### 6.4 状态反馈

- 成功使用绿色，错误和删除使用红色，警告使用黄色，信息使用蓝色。
- 状态条和 toast 使用对应 soft 背景、语义文字和细边框，不使用纯色大面积填充。
- 加载、空状态、错误和无结果必须占用稳定布局，不得导致周围区域跳动。

## 7. 键盘与焦点

- 主启动器和 Panel 默认将焦点交给宿主管理的主输入框。
- 方向键移动列表选择，Enter 执行主动作，Escape 返回上一层或隐藏当前界面。
- 设置的插件 tab 中，`Ctrl+F` 聚焦插件名称筛选框；Panel 内有本地搜索时沿用同一规则。
- 创建型 Panel 可使用 `Ctrl+N`，但必须与 Manifest 和 Host Key 路由声明一致。
- Tab 与 Shift+Tab 按视觉顺序移动焦点；焦点不得跳入隐藏区域。
- 快捷键处理只在对应页面或 Panel 激活时拦截，不影响其他设置 tab 或宿主默认行为。
- 鼠标点击与键盘选择必须更新同一个活动状态，不维护两套相互冲突的焦点模型。

## 8. 滚动、空状态与文案

- 页面只有一个主要滚动容器；侧栏和详情确需独立滚动时，边界必须清晰。
- 虚拟滚动条轨道固定在容器边缘，thumb 最小高度为 24px，点击和拖动不得改变列表布局。
- 空状态由领域图标、短标题和一句下一步组成；不展示产品宣传或功能说明。
- 占位符描述当前可输入内容，不写键盘教程。
- 状态文案优先说明结果，例如“已保存”“加载失败”，避免只显示模糊的“成功”或“错误”。
- 中文界面使用简洁、稳定的术语；同一概念在主界面、设置页和插件中保持同名。

## 9. 公开插件附加规则

- 开发前同时阅读 `docs/plugin-sdk/public-plugin-developer-guide.md` 和本规范。
- Panel 与子窗口通过 Host update 设置 `data-theme`，不得假设初始主题永远是 Dark。
- 使用宿主字体和公开 CSS 变量；插件 CSP 下不得依赖远程字体、远程样式或网络图片。
- 插件资产、HTML、CSS 和 JS 保持在插件包边界内，不为统一视觉修改宿主源码。
- 优先参考与输出模式相同的受控示例；Panel 管理界面优先参考 `/notes`、`/quicklinks` 和 `/clipboard-history`。
- 插件图标遵守 SDK 的固定 PNG 合同；界面内部的操作图标使用可内联的安全资源或已有图标方案。

## 10. 验收清单

每个 UI 变更完成前逐项检查：

- [ ] Light 与 Dark 都已渲染检查，主要按钮没有反色错误。
- [ ] 主界面、设置 tab、Panel 或插件详情的结构与同类页面一致。
- [ ] hover、focus、selected、disabled、loading、empty、error 状态均可辨认。
- [ ] 主输入框和筛选输入框在空值时显示正确占位符。
- [ ] 键盘入口、方向键、Enter、Escape、Tab 和适用的 `Ctrl+F` 已验证。
- [ ] 选中项、长文本、状态文字和虚拟滚动条没有重叠。
- [ ] 图标、按钮、输入框和列表项尺寸稳定，不因动态内容产生布局位移。
- [ ] 新颜色使用语义 token；插件只使用公开 Host CSS 变量或其派生值。
- [ ] 不存在装饰性投影、无意义渐变、嵌套卡片或过大的圆角。
- [ ] 强制颜色模式和可访问名称没有因样式修改而退化。
- [ ] 宿主 UI 运行相关前端测试；插件运行自身测试，并在真实 Host 中完成最终交互验收。
